# 研究用RPGプロトタイプ 仕様書

## 1. 概要

### 1.1 目的

本ゲームは、修士研究「生成AIを用いた自由入力機能の導入が、プレイヤーの対話行動およびゲーム体験に与える影響」のために開発する研究用RPGプロトタイプである。

プレイヤーが小規模な街を探索し、NPCとの会話からクエスト達成に必要な情報を収集するゲームとする。

本研究では、NPCとの対話方式の違いがプレイヤーのゲーム体験に与える影響を比較する。

### 1.2 実験条件

基本的に以下の2条件を想定する。

#### 条件A：選択肢型NPC対話

NPCとの会話において、ゲーム側があらかじめ用意した選択肢からプレイヤーが発言を選択する。

例：

```text
NPC：
「この街について何か知りたいことがあるのか？」

[街について聞く]
[最近起きた事件について聞く]
[何も聞かない]
```

すべてのNPC発言・プレイヤー選択肢・会話分岐は事前に用意する。

#### 条件B：生成AIを利用したNPC対話

基本的な会話構造は選択肢型と同様とするが、プレイヤーが自由入力によってNPCに質問できる。

例：

```text
NPC：
「この街について何か知りたいことがあるのか？」

[街について聞く]
[最近起きた事件について聞く]
[自由入力]
```

自由入力を選択した場合、プレイヤーが文章を入力し、生成AIによってNPCの返答を生成する。

生成AIにはNPCごとの役割・性格・知識・ゲーム内設定などをシステムプロンプトとして与える。

# 2. ゲームコンセプト

## 2.1 ジャンル

小規模探索型RPG

## 2.2 ゲームの目的

プレイヤーは街を探索し、複数のNPCと会話することでクエスト達成に必要な情報を集める。

最終的に必要な情報を揃え、クエストを達成する。

## 2.3 想定プレイ時間

1プレイあたり約10～20分程度を目標とする。

研究実験に使用するため、プレイ時間が長くなりすぎないようにする。

## 2.4 ゲーム規模

研究用プロトタイプであるため、大規模なコンテンツ量は必要としない。

以下程度の規模を想定する。

* 街：1エリア
* NPC：5～10人程度
* クエスト：1件
* 戦闘：実装しない
* 成長システム：実装しない

---

# 3. ゲームフロー

基本的なゲームフローは以下とする。

```text
(ゲーム開始)プレイヤーが街にいる
 ↓
NPCからクエストを受注
 ↓
街を自由に探索
 ↓
NPCと会話
 ↓
NPCから情報を収集
 ↓
必要なアイテムを揃える
 ↓
クエスト達成
 ↓
ゲーム終了
```

ゲーム開始時に、プレイヤーが何をすればよいか理解できるようにクエストを提示する。

# 7. 選択肢型対話

## 7.1 基本仕様

NPCとの会話中、プレイヤーに複数の選択肢を提示する。

例：

```text
NPC：
「何か聞きたいことがあるのか？」

> 街について聞く
  最近の事件について聞く
  何も聞かない
```

選択肢の数は2～4個程度を基本とする。


## 7.2 選択肢操作

* 上キー：選択肢を上へ移動
* 下キー：選択肢を下へ移動
* Enter：選択肢を決定

---

# 8. 自由入力対話

## 8.1 基本仕様

生成AI条件では、会話中に「自由入力」を選択できる。

例：

```text
NPC：
「何か聞きたいことがあるのか？」

[街について聞く]
[最近の事件について聞く]
[自由入力]
```

自由入力を選択すると入力欄を表示する。

```text
┌──────────────────────────────┐
│ NPC名                         │
│                              │
│ 「何を聞きたい？」            │
│                              │
├──────────────────────────────┤
│ ここに質問を入力              │
└──────────────────────────────┘

              [送信]
```

# 9. 生成AIシステム

## 9.1 API

OpenAI APIを使用する。

UnityからHTTPリクエストを送信し、NPCの返答を取得する。

現在の実装ではChat Completions APIを使用する。

## 9.2 AIモデル

実験では使用するモデルを固定する。

モデルを変更した場合、実験結果に影響する可能性があるため、実験開始後はモデルを変更しない。

現在のプロトタイプでは以下を使用する。

```text
gpt-5.6-luna
```

※ 実験開始前に使用可能なモデル・API仕様を確認し、必要に応じてモデルを更新する。

## 9.3 NPCプロンプト

NPCごとに異なるシステムプロンプトを設定できるようにする。

プロンプトには以下の情報を含める。

```text
あなたは○○というNPCです。

【名前】
○○

【役割】
○○

【性格】
○○

【背景】
○○

【知っている情報】
○○

【知らない情報】
○○

【クエストに関する情報】
○○

【会話ルール】
- NPCの設定を維持する
- ゲーム内に存在しない情報を勝手に作らない
- プレイヤーの質問に自然な日本語で回答する
- 必要以上に長い回答をしない
```

# 10. AI対話の制約

研究目的のため、生成AIがゲーム進行を破壊しないことを重視する。

以下を基本ルールとする。

* NPCの設定を逸脱しない
* 存在しないNPCを作らない
* 存在しない場所を作らない
* 存在しないアイテムを作らない
* クエストの正解情報を勝手に変更しない
* プレイヤーにゲーム外の情報を提示しない
* AI自身について説明しない
* 極端に長い回答を生成しない
* 日本語で回答する

---

# 11. 会話状態管理

DialogueManagerで会話状態を管理する。

想定する状態：

```text
FreeMove
InDialogue
InChoice
InTyping
```

## FreeMove

通常の探索状態。

プレイヤーの移動・カメラ操作が可能。

## InDialogue

NPCとの通常会話中。

プレイヤーの移動を停止する。

Enterなどで会話を進める。

## InChoice

選択肢を選択している状態。

プレイヤーの移動を停止する。

上下キーで選択肢を移動する。

## InTyping

自由入力中。

プレイヤーの移動を停止する。

TMP_InputFieldで文章を入力する。

送信ボタンを押すことでAIへ入力を送信する。

---

# 12. 会話終了処理

AIの返答表示中はプレイヤーを操作可能にしない。

AIの返答を表示した後、プレイヤーがEnterなどで会話を進め、ダイアログパネルが閉じられた時点でプレイヤー操作を復帰する。

重要：

```text
AI返答表示
 ↓
プレイヤー操作不可
 ↓
Enter
 ↓
会話終了
 ↓
DialoguePanelを非表示
 ↓
プレイヤー操作可能
```

AI返答を表示した時点では`SetTypingMode(false)`などによってプレイヤー操作を復帰させない。

# 16. ChatGPTClient

## 16.1 責務

`ChatGPTClient`はOpenAI APIとの通信のみを担当する。

UI制御やプレイヤー操作制御は行わない。

## 16.2 入力

```text
userText
systemPrompt
```

## 16.3 出力

```text
AIが生成したNPCの返答
```

## 16.4 APIキー

APIキーをUnityシーンやGit管理対象のファイルに直接記述しない。

研究用ローカル環境では以下のような方法で管理する。

```text
Assets/Resources/openai_key.txt
```

このファイルはGit管理対象から除外する。

# 18. ログ形式

CSV形式で保存する。

例：

```csv
participant_id,timestamp,event_type,npc_id,player_input,npc_response
001,2026-09-22 10:00:01,dialogue_start,npc_01,,
001,2026-09-22 10:00:05,choice,npc_01,街について聞く,

```

ログは後から統計解析できる形式にする。

# 25. Claude Codeによる開発ルール

Claude Codeが本仕様書を参照してUnity MCP経由で開発することを想定する。

## 25.1 基本ルール

* 本仕様書を最優先の仕様として扱う。
* 既存実装を確認してから変更する。
* 不要な既存機能を削除しない。
* 既存のクラス責務を尊重する。
* 1回の変更で大量のファイルを変更しない。
* Unity Consoleのエラーを確認する。
* コンパイルエラーが発生した場合は修正してから次の作業へ進む。
* Unity MCPで実際のUnityプロジェクトの状態を確認する。
* 推測だけでUnityの状態を判断しない。

## 25.2 コード変更時

コードを変更する場合は、

1. 対象ファイルを確認
2. 現在のコードを確認
3. 変更理由を確認
4. 最小限の変更を行う
5. Unityでコンパイル
6. Consoleエラーを確認
7. 必要に応じて修正
8. 動作確認

の順番で進める。

## 25.3 研究仕様の変更

以下を勝手に変更しない。

* 実験条件
* NPCの知識
* クエスト達成条件
* ログ項目
* AIモデル
* AIプロンプト
* 会話方式

変更が必要な場合は、まず変更内容と研究上の影響を説明する。
