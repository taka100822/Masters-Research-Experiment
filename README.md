# 1. 研究と実験

## 1.1 目的

修士研究「生成AIを用いた自由入力機能の導入が、プレイヤーの対話行動およびゲーム体験に与える影響」のための研究用RPGプロトタイプ。プレイヤーは小さな村を**5分間自由に探索し**、村人と話す。NPCとの**対話方式の違い**がプレイヤーの対話行動とゲーム体験に与える影響を比較する。

## 1.2 実験条件

| 条件 | 対話方式 |
|---|---|
| **A：選択肢のみ** | ゲーム側が用意した選択肢からプレイヤーが発言を選ぶ |
| **B：自由入力のみ** | 話しかけるとNPCの最初のセリフ（あいさつ）が出て、そのあとは選択肢を出さず、文章を入力して生成AIのNPCと話す。「会話をやめる」ボタンで会話を終える（4.3） |

* 条件は話題セットやNPCに結び付けず、「参加者が今どちらの条件で遊んでいるか」という**全体設定**として持つ。同じNPC・同じ話題セット・同じ会話データとプロンプトを使い、条件Aでは選択肢だけ、条件Bではあいさつのあと自由入力だけで話す
* 設定は実験者がタイトル画面の開発者用モーダルで行う（3.1）。実装上は`ExperimentSettings.FreeInputOnly`（条件B）のとき、`DialogueManager`が選択肢を出さずに自由入力へ進む（4.2・4.3）

## 1.3 話題セットとカウンターバランス

参加者は条件A・Bの両方を遊ぶ。同じ村人と同じ話を2回すると2回目は新しさがなくなるので、**構成をそろえた話題セットを2つ**用意する（5章）。

* 話題セット1：商人ヴィクター・村人ルカ・薬師ティム・村長ニコラ・鍛冶屋ヤニス・料理人ステフ
* 話題セット2：大工シャック・先生ディルク・パン屋マヌ・布屋パウ・地主マイケル・漁師カワイ

話題セットと条件を固定のペアにすると、体験の違いが対話方式によるのか話題の内容によるのか区別できない。そのため話題セットと条件は独立させ、参加者を次の4グループに均等に振り分ける。

1. 条件A×セット1 → 条件B×セット2
2. 条件A×セット2 → 条件B×セット1
3. 条件B×セット1 → 条件A×セット2
4. 条件B×セット2 → 条件A×セット1

* グループは参加者IDの番号から自動で決まる（2.5）。実験者は条件・話題セットを選ばない

* 2つのセットで同じにするもの：村・NPCの人数と位置・会話の型（5.3）・話題の数と長さ・自由入力の場面
* 違うもの：村人の名前・性格・話題・衣装（5.2）
* 村の地形は2回目には覚えているが、順番を入れ替えているので条件の差にはならない

**条件A**では、全員の話題2つずつ（1セット12個）は**すべて選択肢だけで聞ける**。**条件B**では選択肢がないので、話題は参加者が質問したときにAIが話す（プロンプトの【知っている情報】。4.5）。聞けた話題の数は条件によって変わりうる（1.8）。

## 1.4 条件以外の差を小さくする

ゲームとしての面白さより、実験条件の統制を優先する。マップ・NPCの配置・会話の型と話題の量・制限時間・UI・操作・BGM/SE・グラフィックは、両条件・両セットで同じにする。主な違いは対話方式だけにする。

* 2つの話題セットの対応は5.6、会話の型の統一は5.3
* ミニマップ・NPCの名前表示・残り時間・説明画面の文は、両条件・両セットで同じように出る
* 音量・視点感度は**保存せず、起動するたびに初期値に戻す**（前の参加者の設定が次の参加者に引き継がれないように）

## 1.5 研究データの再現性

Unityバージョン・AIモデル・API仕様・NPCプロンプト・会話データ（話題セット）・ゲームバージョン・実験日時・実験条件を固定し、記録する。特に条件Bでは、**実験期間中にプロンプトやモデルを変更しない**。ログには使ったプロンプトの識別子とハッシュ値を残して、後から確認できるようにする（6章）。

## 1.6 研究仕様の変更ルール

次のものは勝手に変更しない：実験条件、NPCの知識（話題）、制限時間、ログ項目、AIモデル、AIプロンプト、会話方式。変更が必要なときは、まず変更内容と研究上の影響を説明する。

## 1.7 課題の変更：クエストから自由探索へ（2026-10-09）

最初は「依頼を受けて手がかりを集めるクエスト」で比較していたが、2026-10-09に「村を5分間自由に探索する」課題に変えた（ブランチ`feature/Exploring-city`）。変えた理由・決めたこと・研究への影響は[`docs/history.md`](docs/history.md#2026-10-09-課題の変更クエストから自由探索へ)。

* クエスト版の実装と仕様は`main`ブランチ（コミット`36a2b1b`）とgitの履歴にある。戻すときはそこから
* クエスト用のクラス・データはファイルとしては残してある（8章）
* 研究上の主な違い：達成条件がなくなり、誰と・どれだけ話すかが参加者に任される。プレイ時間は全員5分にそろうが、条件Bでは返答待ちの時間も5分に含まれる（summary.csvの`ai_wait_total`で把握する。6.7）

## 1.8 条件Bの変更：選択肢＋自由入力から自由入力のみへ（2026-10-29）

条件Bは最初「選択肢＋自由入力」（選択肢に「入力する」が加わる）だったが、2026-10-29に「自由入力のみ」に変えた。決めたこと・研究への影響は[`docs/history.md`](docs/history.md#2026-10-29-条件bを自由入力のみにする)。

* 研究上の主な違い：条件Bでは話題を選択肢で聞けないので、聞けるかどうかは参加者の質問しだいになる（1.3の大前提は条件Aだけのものになった）。比べるのは「選択肢」と「自由入力」という対話方式そのものの違い
* AIは会話の履歴を持たない（毎回、システムプロンプト＋今回の入力だけ）。履歴を持たせるかは保留（10.4）

# 2. ゲームの概要

## 2.1 規模

* ジャンル：小規模な探索型RPG（戦闘・成長システム・クエストなし）
* プレイ時間：探索5分（＋説明画面）
* マップ：村1つ（`Assets/MainScene.unity`、購入アセットのVillageを使用）
* NPC：6人。話題セットごとに名前・性格・話題・衣装が変わる（5.2）
* 話題セット：2つ。1回のプレイでは設定で選んだ1つだけを使う
* セーブ：なし（1回のプレイを最初から最後まで行う）

## 2.2 ゲームの流れ

```text
タイトル画面（実験者が開発者用モーダルで参加者IDを設定）
 ↓ はじめる
チュートリアル（別の場所。2.4）
 ↓ Enter
説明画面（村の上で、操作できない状態で表示。3.7）
 ↓ Enter
探索（5分）：自由に歩き、好きな村人と好きなだけ話す
 ↓ 5分たつ（会話中なら、その会話の区切りまで待つ。5.1）
アンケート画面（3.7）
 ↓ 1回目のあとは、2回目のチュートリアルへ（2.5）
```

1人が2回（条件A・Bを1回ずつ）遊ぶ。2回目のアンケートのあとは、おわりの画面（操作不可）で止まる。

プレイ中はいつでも`Q`で設定パネルを開ける（探索中のみ）。設定パネルを開いている間は残り時間も止まる。参加者がタイトルへ戻る手段は無い。実験者だけが開発者用コマンド（`Ctrl+Shift+T`。2.5）でタイトルへ戻せ、そのとき進み具合（残り時間を含む）はリセットされる。

## 2.3 操作

| キー | 操作 |
|---|---|
| WASD | 移動 |
| マウス | カメラ操作 |
| Enter | 説明画面を閉じる／話しかける／会話を進める／選択肢を決定する |
| ↑ ↓ | 選択肢を選ぶ |
| Q | 設定パネルを開く・閉じる（探索中のみ） |
| マウスクリック | 自由入力の「送信」（空欄では押せない）・「会話をやめる」ボタン・設定パネル・タイトル画面の操作 |

移動・カメラは Starter Assets Third Person Controller（購入アセット）の標準入力。ジャンプはこのゲームに要らないので無くしてある（Spaceを押しても何も起きない。7.3）。会話まわりの入力は`DialogueManager`が`Keyboard.current`を直接見ている。

## 2.4 チュートリアル

各プレイの前に、村とは別の小さな場所（`TutorialScene`）で操作を練習する。実験者が口頭で操作を説明しなくてよいようにし、説明を全員同じにするため。決めたこと・研究への影響は[`docs/history.md`](docs/history.md#2026-10-29-チュートリアル)。

**流れ（1プレイ）**

```text
タイトル画面 → はじめる（2回目は、1回目のアンケート画面から）
 ↓
TutorialScene：やることを1つずつこなす（時間制限なし）
 ↓ 最後に「準備ができたら Enter」
MainScene：説明画面（3.7）→ Enter → 本番5分
```

* **各プレイの前に毎回**行う。その回の条件の話し方だけを練習する（条件Aの回は選択肢、条件Bの回は自由入力）
* **1回目は全部、2回目は簡易版**（下の「2回目の簡易版」）。歩き方・設定パネルは1回目で覚えているので、2回目は新しい話し方の練習だけにする
* **Shiftを押しながら「はじめる」**を押すと、チュートリアルを飛ばしてMainSceneへ入る（実験者の動作確認用）

**2回目の簡易版**

今が2回目（`ExperimentConfig.Round == 2`。2.5）なら簡易版にする。2回目は1回目と話し方（条件）が変わるので、話しかけと新しい話し方だけを練習する。

* 簡易版でやること：下の表の **2 → 3 → 6** だけ（1 歩く・4 クリス・5 設定パネルは出さない）。進む条件は通常版と同じ。札の文も、2の1行目以外は通常版と同じ
* 簡易版の2の札は、1行目を`今回は、村人との話し方が前回と違います。`に替える（`今回は、村人との話し方が前回と違います。↵案内人ケビンに近づいて [Enter] で話しかけましょう`）。2回目は話し方が変わるので、話しかける前に知らせる。どう違うかは3の札で練習する。「条件」という言葉は出さない（3.1と同じ考え）。実装は`TutorialGuide.StepText(2)`（`steps == ShortSteps`のとき）
* エディタでTutorialSceneを直接Playしたときは1回目扱い（通常版）

**場所**

* プレイヤーのいる所を中心に、一辺40mの平らな草地（`TutorialGround`）。歩けるのは一辺30mの中だけ（見えない壁`TutorialWalls`）
* 空・ライティング・プレイヤー・カメラ・会話UI・設定パネル・ミニマップは本番と同じ（MainSceneを複製して作るため）。BGMだけはチュートリアル用の曲（7.4）。説明画面・残り時間・制限時間（`ExplorationTimer`）はない
* ミニマップの地図は草地と歩ける範囲の境目だけの画像（`Assets/Texture/minimap_tutorial.png`）。村人は本番と同じ白い丸

**案内役の村人**（話題セットとは別。名前はNBA選手から）

| npcId | 名前 | 位置（プレイヤーの向きから） |
|---|---|---|
| `TUT001` | 案内人ケビン | 右3m・前6m |
| `TUT002` | 旅人クリス | 右5m・前11m |

* 見た目は本番の村人のモデルを使い、**今回の村では使わない方の衣装**（もう一方の話題セットの衣装）にする。例：話題セット1の回のケビンは、セット2のNPC001（大工シャック）の衣装
* セリフ・プロンプトは村と関係のない軽い話（天気・広場・旅）。本番の村人の名前・居場所・話題には触れない。セリフ・プロンプトの全文はスプレッドシート（4.8・4.7）

**やること**（画面上部中央の「やること」の札。できたら「できました！」を出し、1秒後に次へ）

| # | 札の文（A：条件A、B：条件B。`↵`で改行） | 次へ進む条件 |
|---|---|---|
| 1 | `[W][A][S][D] で歩いてみましょう。↵マウスで見回せます` | 横に合計3m歩いた |
| 2 | `右上の地図の白い丸が村人です。↵案内人ケビンに近づいて [Enter] で話しかけましょう` | ケビンとの会話が始まった |
| 3 | A：`[↑][↓] で選んで [Enter] で決めましょう。↵会話を最後まで進めます`／B：`話したいことを書いて「送信」を押しましょう。↵返事を読んだら「会話をやめる」で終えます` | ケビンとの会話を閉じた（その会話で、Aは選択肢を1回以上決めた、Bは返事を1回以上表示した） |
| 4 | A：`旅人クリスにも話しかけて、↵会話を最後まで進めましょう`／B：`旅人クリスにも話しかけて、何か聞いてみましょう。↵終わったら「会話をやめる」で終えます` | クリスとの会話を閉じた（条件は3と同じ） |
| 5 | `[Q] で設定を開けます。音の大きさを変えたり、↵動けなくなったときに「初期位置に戻る」を押したりできます。↵開いて閉じてみましょう` | 設定パネルを開いて閉じた |
| 6 | `本番では右上に残り時間が出て、5分たつと自動で終わります。↵残り1分になると、残り時間の色が変わります。↵準備ができたら [Enter]` | Enter → MainSceneへ |

* 札は残り時間の窓と同じ見た目（樫色＋真鍮の縁）で、幅720、画面上端から16px。文字20px・中央揃え。会話中・設定パネル表示中も出たまま（設定パネルの暗幕の下になる）
* **改行**：札の文は文の切れ目で手で改行してある（1行は全角30字まで。札の幅672px・20pxで約33字入る）。そのうえで3.4と同じ処理（`JapaneseLineBreaker.Format`）で文節の途中では折り返さないようにする
* 札の高さは文の行数に合わせて伸びる（最小72。`TutorialGuide.minPanelHeight`）。「できました！」の行が増えても窓からはみ出さない
* 順番どおりにしか進まない（例：1の前にケビンと話しても、2は「話しかけた」にならない。ケビンと話すこと自体はできる）
* **クリスは4の札が出るまで話しかけられない**。4より前にクリスに近づくと、話しかけ案内の札（3.3）は`[Enter] 旅人クリスと話す`の代わりに`先に案内人ケビンと話しましょう`を出し、Enterを押しても会話は始まらない（ケビンの名前は頭上の名前と同じ）。頭上の吹き出し・名前・地図の白い丸はそのまま。4・5の間は普通に話せる。簡易版はクリスの番が来ないので、最後まで話せない。ログには何も書かない。実装は`TutorialGuide.CanTalkTo`・`TalkBlockedHint`（[`docs/history.md`](docs/history.md#2026-10-30-クリスに先に話しかけられないようにする)）
* 6を出したら、移動・話しかけ・設定パネルを止める（`DialogueManager.LockForTutorialEnd`）。Enterは札が出た次のフレームから受け付ける
* 音量・視点の速さはシーンごとに初期値に戻るので、チュートリアルで変えても本番には引き継がれない（1.4）

**会話データとプロンプト**

* 条件A：`Assets/Resources/dialogue/Tutorial/TUT001.csv`・`TUT002.csv`（あいさつ → 選択肢2つ → 一言 → 別れ）
* 条件B：`Assets/Resources/PromptData/Tutorial/TUT001`・`TUT002`（4.5のテンプレートに沿う。【村の人たち】は書かず、村のことは知らないと答える）
* 本番と同じ`DialogueManager`の仕組み（4章）で動く。チュートリアル中（`TutorialGuide.Active`）は読む場所だけが`Tutorial/`になる

**ログ**

* 本番とは**別のファイル**：`{参加者ID}_{条件}_S{話題セット番号}_{開始日時}_tutorial.csv`（形式は6.6と同じ）。summary.csvには何も足さない
* ふだんのイベント（`dialogue_start`・`npc_line`・`choice_select`・`free_input_submit`・`ai_response`・`settings_open`など）に加えて、次を書く

| event_type | いつ | 主な記録内容 |
|---|---|---|
| `tutorial_start` | 始めたとき | `detail`に`condition=A`／`B`・`mode=full`（通常版）／`short`（2回目の簡易版）・`round=1`／`2`（例：`condition=B;mode=short;round=2`） |
| `tutorial_step` | やることを1つ終えたとき | `detail`に`step=1`〜`5`（簡易版でも番号は通常版の表のまま。`2`・`3`だけが出る） |
| `tutorial_end` | 最後にEnterを押したとき | — |

* 終わり方（`session_end`の`reason`）は`tutorial_end`（途中でタイトルへ戻ったら`back_to_title`）
* `ai_response`の`detail`のプロンプトは`prompt=Tutorial/TUT001`のようになる

**作り方**：シーンは手で作らず、Unityのメニュー **Tools → 研究用 → チュートリアルのシーンを作り直す**（`TutorialSceneBuilder`）で、MainSceneから作る。MainSceneを複製し、村（`Background`・`WaterBlockers`）とNPC003〜006を消し、NPC001・002を案内役に作り替え、草地・壁・札・ミニマップの地図を置いて、ビルド設定（タイトルの次）に足す。**MainSceneのプレイヤー・UI・NPCを変えたら作り直す**（作り直すと`TutorialScene`の手での変更は消える）

**実装**：`TutorialGuide`（`TutorialScene`の`GameManager`に付ける）が進み具合を持つ。`DialogueManager`は会話の開始・選択の決定・AIの返事の表示・会話の終わり・設定パネルの開閉を`TutorialGuide.Instance`に知らせる（MainSceneでは`Instance`が無いので何もしない）。話しかけてよい相手かどうかも`HandleFreeMoveInput`が`TutorialGuide.CanTalkTo`に聞く

## 2.5 1人2回の進め方

実験者は**参加者IDだけ**を入れる。条件・話題セットはIDの番号からグループ（1.3）を出して自動で決め、2回分を続けて進める。条件・話題セットを手で選ぶと、グループと違う組み合わせを選ぶ・2回目に切り替え忘れるといった人為ミスが起きうるため。決めたこと・研究への影響は[`docs/history.md`](docs/history.md#2026-10-29-1人2回の自動進行)。

```text
タイトル画面（実験者が参加者IDを入れる）→ はじめる
 ↓
【1回目】チュートリアル（通常版）→ 説明画面 → 探索5分 → アンケート画面
 ↓ 参加者が「アンケート回答完了」→ 確認で「はい」
【2回目】チュートリアル（簡易版）→ 説明画面 → 探索5分 → アンケート画面
 ↓ 参加者が「アンケート回答完了」→ 確認で「はい」
おわりの画面（操作不可）
```

* グループ＝`(番号 − 1) を4で割った余り ＋ 1`。番号はIDの末尾の数字（`P001`→1→グループ1、`P006`→6→グループ2、`P012`→12→グループ4）

| グループ | 1回目 | 2回目 |
|---|---|---|
| 1 | A・S1 | B・S2 |
| 2 | A・S2 | B・S1 |
| 3 | B・S1 | A・S2 |
| 4 | B・S2 | A・S1 |

* アンケートは同じPCのGoogleフォーム「ゲーム体験アンケート」（ゲームの外）で答える。アンケート画面の「アンケートを開く」で、プレイヤーIDと回が入った状態のフォームがブラウザで開く（3.7）。回答も、アンケート画面での操作もログに書かない（本番のログは時間切れの`session_end`で閉じているため）
* アプリは同時に1つしか起動しない（Player Settingsの「Force Single Instance」。2つ起動すると同じ`summary.csv`に両方が書くため）
* ログのファイルは1回のプレイごと（6章）。1人分で本番2つ＋チュートリアル2つ。`session_start`・`tutorial_start`の`detail`に`round=1`／`2`が入る
* 途中で落ちた・やり直すときは、開発者用モーダルの「始める回」で「2回目から」を選ぶ（3.1）。開発者用コマンドでタイトルへ戻ったとき（下）は参加者ID・回が残るので、そのまま「はじめる」でその回を最初（チュートリアル）からやり直せる

**開発者用コマンド：タイトルへ戻る**

* `Ctrl+Shift+T`を押すと、確認なしで`back_to_title`でログを閉じてTitleSceneへ戻る（残り時間も含めて最初から。参加者ID・回は残る）
* 効くのはTutorialSceneとMainSceneで、**どの状態でも**（説明画面・会話中・選択肢中・自由入力中・設定パネル表示中・アンケート画面・おわりの画面）。自由入力中でも欄に文字は入らない（`Ctrl`を押しながらなので）
* 画面のどこにも書かない（参加者に見せないため。以前は設定パネルにボタンがあったが外した。3.8）。3つ同時押しなので、参加者が誤って押すことはまず無い
* アンケート画面・おわりの画面では、本番のログは時間切れの`session_end`（`time_up`）で閉じているので、ログには何も足さない
* 実装：`DialogueManager.Update()`の頭で`Keyboard.current`の`ctrlKey`・`shiftKey`が押されていて`tKey.wasPressedThisFrame`なら`BackToTitle()`（`ExperimentLogger.EndSessionNow("back_to_title")`→`Time.timeScale = 1`→`SceneManager.LoadScene("TitleScene")`）。以前`SettingsPanelUI.OnClickTitle()`がしていた処理を移す
* おわりの画面にはボタンが無い。実験者はアプリを閉じ、次の参加者は起動し直してIDを入れる

**実装**：`ExperimentConfig`が参加者ID・回（`Round`）を持ち、条件・話題セットはIDと回から計算する（`GroupOf`・`ConditionOf`・`TopicSetOf`）。アンケート画面の「はい」で`EndScreenUI`が`ExperimentConfig.AdvanceToSecondRound()`を呼んでTutorialSceneを開く

  | どちらも書ける | `OK`（漆喰色） |

  | 書けるが、`summary_pending_….csv`（6.7）が残っている | `OK（summary.csvに写していない集計が1件あります）`（真鍮色） |

  * ログを作れないとき、ゲームは止まらずに進み、ビルド版では気づけない（`ExperimentLogger`はConsoleにエラーを出すだけ）。失敗と出たら、ビルドを書き込める場所へ移す（保存先は下の「ログ保存先：」）
  * 失敗しても「決定」「はじめる」は止めない。ログ・summary.csvには何も足さない
  * **実装**：`ExperimentLogger`の`CanWrite`・`IsSummaryLocked`・`CountPendingSummaries`を`TitleMenuUI.CheckLogWrite`（`OpenDeveloperModal`から）が呼び、`logCheckText`に出す
* **同じIDの注意**：IDを打つたびに（モーダルを開いたときも）、ログの保存先にそのIDの本番のログ（`{ID}_…csv`。`_tutorial`は数えない）がいくつあるかを数え、1つ以上あればエラーの行（`ErrorText`）に`注意：このIDの本番のログが既に2件あります`と出す。打ち間違えて前の人と同じIDで始めないように
  * **止めない**（「決定」は押せる）。「2回目から」でやり直すときは1回目のログがあるのが正しいため。実験者が見て判断する
  * IDの大文字・小文字は区別しない（`p005`も`P005`と同じに数える）。`P1`と`P10`は取り違えない（IDの後ろの`_`まで比べる）

  * **実装**：`ExperimentLogger.CountSessionLogs`を`TitleMenuUI.UpdateExistingLogWarning`が呼ぶ
* **決定**（`CloseButton`、`TitleMenuUI.closeButton`）：真鍮の地。値を反映して閉じ、タイトルの設定表示も更新する。参加者IDが空なら閉じない（「参加者IDを入力してください」）。末尾に1以上の番号が無いときも閉じない（「参加者IDの末尾に番号を付けてください」）
* **キャンセル**（`CancelButton`、`TitleMenuUI.cancelButton`）：枠線だけ。入力した値を捨てて閉じる。次に開いたときは`ExperimentConfig`の値が入り直す

**設定の受け渡し**

* タイトルで設定した値はstaticな`ExperimentConfig`（`ParticipantId`・`Round`。`Condition`・`TopicSet`はそこから計算。2.5）に置き、各シーンの`ExperimentSettings`が起動時（`Awake`）に読む。読んだ値はConsoleに`[Experiment] participant=… condition=… set=…`と出る

* ファイルには保存しない。アプリを起動し直すと初期値（IDは空・1回目）に戻る

**自由入力の窓**（`InputPanel`。条件Bだけ）

```text
 ┌──────────────────────────────────────────────────────────┐
 │ 薬師ティムに話しかける                                      │ ← 小見出し（InputHeaderText・煤色）
 │ ┌────────────────────────────────┐ [ 会話をやめる ] [ 送信 ] │ ← 入力欄（漆喰の地・濃い文字）
 │ │ 聞きたいことを書いてください       │                       │
 │ └──────────────────────────────────┘                       │
 └──────────────────────────────────────────────────────────┘
 ┌ 会話窓（直前のセリフはそのまま表示）─────────────────────────┐
```

* 会話窓の上（画面下から230px、看板にかからない位置）に、会話窓と同じ幅960×高さ104で出す。会話窓（直前のセリフ）は表示したまま。入力欄の幅は「会話をやめる」の分だけ縮めてある（`InputField`の`SizeDelta.x`＝-368）
* **送信**（`SendButton`）：真鍮の地。入力欄が空（空白だけを含む）の間は押せない。Enterでは送らない（4.1）
* **Enterを押したとき**：送らない代わりに、次のフレームで入力欄を選び直し、カーソルを文の最後に置く（入力欄は1行なので、Enterで選択が外れて続けて打てなくなるため）。書いた文章は消さない。入力欄に文字があるときは、「送信」の地を漆喰色に向けて明るくして戻し（0.5秒）、操作案内`入力したら「送信」を押してください`を1秒間だけ真鍮色にする。空欄のときは選び直すだけ
  * AIの返事を待っている間（入力の窓が隠れている間）は、Enterを押しても何もしない（`InTyping`のままだが、合図を出さない）
  * IMEの変換を確定するEnterでは何もしない：Enterを押したフレームか、その1つ前のフレームで変換中の文字があれば、確定とみなす（入力はInput Systemだけなので、`Keyboard.current.onIMECompositionChange`で変換中の文字を覚えておく）
  * ログには書かない（6.3）
* **会話をやめる**（`CancelButton`→`DialogueManager.OnClickCancelInput`）：枠線だけ。幅160（送信は120）。書きかけの文章（送れなかった文章の残し（4.6）も）を捨てて**会話を閉じる**。ログは`dialogue_end`（`detail`に`end=quit_button`）
* プレースホルダーは「聞きたいことを書いてください」

**話しかけ案内**（`TalkHint`）：近くのNPCがいると、画面下中央（下から48px）に樫色の小さな札で`[Enter] 薬師ティムと話す`と出す（近くのNPCの名前を入れる。文字は子の`TalkHintText`）。NPC頭上の吹き出し（3.5）も同時に出る。会話窓が出ている間は出さない。チュートリアルで、まだ話しかけられない相手（4の札より前のクリス）のときは`先に案内人ケビンと話しましょう`を出し、Enterで会話を始めない（2.4）。

**実装**：`DialogueManager`のInspectorの「Dialogue UI Style」に`keyGuideText`・`talkHintText`・`inputHeaderText`・`choiceRows`・`sendButton`（未設定でも動く）。操作案内の切り替えは`SetKeyGuide`、選択肢の見た目は`UpdateChoiceUI`、送信ボタンの有効・無効は`UpdateSendButton`。自由入力中のEnterの合図は`HandleTypingInput`→`EnterNudge`（「送信」・「会話をやめる」を押したときは`StopEnterNudge`で色を戻す）。▼の揺れは`UIBob`（`Time.unscaledTime`）。

## 3.4 会話の本文の改行

TextMeshProは日本語を1文字ごとにどこでも折り返すので、そのままだと単語の途中で改行されて読みにくい。会話の本文には、表示の直前に次の2つの処理をかける（NPCのセリフ`ShowNode`とAIの返答`ShowAIResponse`の両方。選択肢・名前・操作案内は短いのでかけない）。会話データ・プロンプトは書き換えない。

**1. 文節の途中で改行しない**

* 本文を**文節**（「薬草の」「包みも」「きっと」…）に区切り、改行は文節と文節の間だけで起きるようにする
* 区切りは**BudouX**（Googleの日本語改行用ライブラリ。Chromeの`word-break: auto-phrase`にも使われている。Apache 2.0）の日本語モデル（`Assets/Resources/BudouX/ja.json`。ライセンス表記も同じフォルダ）を使う
* しくみ：文節ごとに`<nobr>…</nobr>`（TMPの改行禁止タグ）で囲み、文節の間に幅ゼロの空白（U+200B）を入れて改行してよい位置にする。1つの文節が1行より長いときは、TMPがふつうに途中で折り返す。`NotoSansJP-Regular SDF`はU+200Bを持つので□にならない
* 元の文にあるTMPのタグはそのまま残し、タグの中は区切らない。手で入れた改行（CSVの`\n`など）もそのまま残す
* BudouXの区切りが辞書の単語と合わないことはある（例：「すれ違った」が「すれ／違った」）。そのときもその区切りの間で改行されるだけ

**2. 入るなら文の終わりの後で改行する**

* 本文の途中にある文の終わり（`。！？!?`）の後ろを改行の候補にする。「！？」のように続くときはまとめて1つの終わりとし、直後に`」』）)`が続くときはその後ろ。本文の最後の終わりは候補にしない
* 前の候補から順に、そこで改行しても**本文が`maxDialogueLines`（3）行以内に収まるときだけ**改行する。収まらない候補は飛ばす
* 行数はその場で`DialogueText`に並べて数える（窓の幅・文字の大きさを変えても正しく働く）。数えられないときは改行を足さない。AIの返答がもともと3行を超えるときは改行を足さない
* 候補は前から順に使うので、文の多い長い返答（主にAI）では、後ろの文どうしが同じ行に並ぶことがある（3行に収めるのを優先する）

```text
村に届く荷物は、いつも村の入り口に置かれるんだ。
薬草の包みもきっとあそこに置かれたはずだよ。
```

* **ログ**（`npc_line`・`ai_response`）には、区切る前の元の文を書く（タグを混ぜない）
* **実装**：`JapaneseLineBreaker`（静的クラス）の`Format(string text, TMP_Text target, int maxLines)`。モデルは最初の1回だけ読む。読めなければ元の文をそのまま返す。`DialogueManager`はパネルを表示してから`Format`を通す（行を数えるため）

## 3.5 NPCの頭上UI

* **初期位置に戻る**：ゲーム開始時の位置・向きへ瞬間移動し、パネルを閉じる。建物の隙間にはまったときなどの救済用。残り時間はそのまま。カメラが村の上空を横切らないよう、Cinemachineに瞬間移動を伝えている（`OnTargetObjectWarped`）
* **閉じる**：`Q`と同じく設定パネルを閉じてゲームに戻る。ボタンの中に`[Q]`を書き、キーでも閉じられることを示す

* 「タイトルへ戻る」ボタンは置かない。参加者が押すと実験をやり直すことになるため。実験者は開発者用コマンド（`Ctrl+Shift+T`。2.5）で戻す

**実装**：「閉じる」ボタンは`SettingsPanelUI.closeButton`→`DialogueManager.CloseSettingsFromButton()`（`InSettings`のときだけ`CloseSettings()`）。MainSceneでは`SettingsPanel`の下に`Backdrop`・`Bg`・`ActionGroup`（`RespawnButton`・`CaptionText`）・`CloseButton`。以前の「Q：閉じる」（`HintText`）は非表示。以前あった`TitleButton`・`ConfirmGroup`と、`SettingsPanelUI`の`titleButton`・`actionGroup`・`confirmGroup`・`confirmTitleButton`・`cancelTitleButton`・`ShowTitleConfirm()`・`OnClickTitle()`は消す（TutorialSceneはMainSceneから作り直す。2.4）

# 4. 会話システム

## 4.1 状態

`GameState`（`Assets/Script/GameState.cs`）。状態を持ち、遷移させているのは`DialogueManager`（`currentState`）。

| 状態 | 内容 |
|---|---|
| `Intro` | 説明画面（3.7）。Enterで閉じて`FreeMove`へ |
| `FreeMove` | 探索中。移動・カメラ操作ができる。近くにNPCがいればEnterで話しかけられる。Qで設定パネル |
| `InDialogue` | 会話中（選択肢なし）。Enterで次へ（条件Bでは自由入力へ） |
| `InChoice` | 選択肢を選んでいる。↑↓で移動、Enterで決定 |
| `InTyping` | 自由入力中。送信はボタンのみ（IME変換中のEnterで誤送信しないよう、Enterでは送らない）。「会話をやめる」ボタンで会話を閉じる（`FreeMove`）。AIの返答待ちの間もこの状態。条件Bだけ |
| `Ended` | 時間切れ後のアンケート画面・おわりの画面。操作不可（ボタンだけ押せる） |
| `InSettings` | 設定パネル表示中。時間停止 |

プレイヤーを止めるときは必ず`DialogueManager.StopPlayer()`を通す。`ThirdPersonController`を無効にするだけでは、走りながら話しかけたときに走りモーションと足音（アニメーションイベント）が続いてしまうため、速度を0にする`StopMotion()`も呼ぶ（7.3）。

## 4.2 会話の進み方

**条件A**：会話は会話データ（CSV）の**ノード**を順にたどる（4.4）。

* 1ノードの選択肢は最大2つ：`choiceA`、`choiceB`（それぞれ空でなければ表示）
* 選択肢が1つも無いノードでは「次へ」の案内だけを出し、Enterで`nextId`へ進む。`nextId=-1`なら会話を終える
* 「なんでもない」「じゃあね」のような選択肢は、`choiceA`／`choiceB`の文として書き、遷移先に終了用のノードを置く
* 時間切れのあとは、次のノード・選んだ先へは進まず、会話を閉じてアンケート画面にする（5.1）

**条件B**：ノード`0`（あいさつ）だけを表示する。選択肢は出さず`[Enter] 次へ`の案内を出し、Enterで自由入力へ進む（4.3）。ノード`0`より先のノードは表示しない

## 4.3 自由入力とAIの返答（条件B）

```text
話しかける → ノード0のあいさつ（[Enter] 次へ）
 ↓ Enter
自由入力の窓を表示（カーソル表示・移動停止）
 ├ 送信ボタン → AIへ送信（返答を待つ間もプレイヤーは動けない）
 │    ↓
 │  AIの返答をNPCのセリフとして表示（[Enter] 次へ）
 │    ↓ Enter
 │  また自由入力の窓へ（何回でも）
 └ 会話をやめるボタン → 会話を閉じる
```

* 話題は**聞かれたら話すだけ**。プロンプトの【知っている情報】に話題1・2が書いてある（4.5・5.4）
* AIは会話の履歴を持たない（毎回、システムプロンプト＋今回の入力だけを送る）
* **実装**：`DialogueManager`の`FreeInputOnly`（`ExperimentSettings.FreeInputOnly`）。`ShowChoicesFromNode`は条件Bでは選択肢を作らず`InDialogue`にし、`HandleDialogueInput`はEnterで`OpenInputMode`を呼ぶ。「会話をやめる」は`OnClickCancelInput`→`CloseDialogue("end=quit_button")`

## 4.4 会話データ（CSV）

`Assets/Resources/dialogue/S{話題セット番号}/`に、NPC1人につき1つのCSV（`{npcId}.csv`）を置く（`DialogueDatabase`が、会話を始めるときに読み込む）。

```text
id, text, nextId, choiceA, choiceA_next, choiceB, choiceB_next, allowInput, action
```

| 列 | 内容 |
|---|---|
| `id` | ノードID |
| `text` | NPCのセリフ（**半角カンマは使えない**。読点「、」を使う） |
| `nextId` | 選択肢が無いときの次のノード（`-1`で終了） |
| `choiceA`／`choiceA_next`、`choiceB`／`choiceB_next` | 選択肢の文と遷移先 |
| `allowInput` | 使っていない（条件Bが「選択肢＋自由入力」だったころ、「入力する」を出すノードの印。列は残してある） |
| `action` | ノードを表示した瞬間に実行する：`topic:<番号>`（話題を聞いた。ログの`topic_heard`）。空なら何もしない |

* **CSVは直接直さない**。スプレッドシートで書いてUnityのメニューから取り込む（4.8）。直接直しても、次の取り込みでシートの内容に戻る
* **会話はいつもノード`0`から始まる**（前に聞いた話題を覚えておく仕組みはない）
* 読み込む場所は`Dialogue/S{話題セット番号}/{csvFileName}`だけ。クエスト版の`Q1/`・`Q2/`・`Common/`のCSVは残してあるが読まない
* クエスト版の`action`（`startQuest`／`clue:`／`complete`）はもう使わない（書くとConsoleに警告が出るだけ）

## 4.5 生成AI

* **API**：OpenAI Chat Completions API（`https://api.openai.com/v1/chat/completions`）に`UnityWebRequest`で送る（`ChatGPTClient`）。`ChatGPTClient`は通信だけを担当し、UIやプレイヤー操作には触れない
* **APIキー**：`Assets/Resources/openai_key.txt`から読む（`.gitignore`済み。GitHubには上げない）
* **モデル**：`ChatGPTClient.cs`の定数`model = "gpt-5.6-luna"`（2026-10-05に動作確認済み）。実験期間中は変えない（1.5）
* **プロンプトの読み込み**：`PromptData/S{話題セット番号}/{npcId}` → `NPCDialogue.promptData` の順に探す（`DialogueManager.LoadPromptData()`）。どれも無ければ送信せず、NPCのセリフとして「……（今は話せないようだ）」を表示してConsoleにエラーを出す
* **プロンプトの形式**：`PromptData`（ScriptableObject）の`systemPrompt`という1つの文字列。名前・性格・知っている情報などは、下のテンプレートに沿って文章の中に書く。全員（1セット6人×2セット＝12個）にある。中身はスプレッドシートで書いて取り込む（4.7）。Inspectorで直接直さない（次の取り込みでシートの内容に戻る）
* **エラー**：通信の失敗・時間切れ（20秒）・返答の解析失敗・APIキーが無い、のどれでもゲームは止まらず、参加者向けの一文を表示する（4.6）

**AIに守らせること**（プロンプトの文面で守らせる。コード側での検査はしていない）

* NPCの設定から外れない。存在しない人物・場所・アイテムを作らない
* 「知っている情報」の内容を変えない
* ゲーム外の情報を出さない。自分がAIであることに触れない
* 80文字以内の日本語で答える

**プロンプトのテンプレート**

```text
あなたは村に住む{{役職}}の{{名前}}です。

【性格】
{{一言で表せる人物像}}

【背景】
{{今何をしているか}}

【村の人たち】
{{そのセットの6人の名前・仕事・居場所（セット内で全員同じ文）}}

【知っている情報】
{{話題1・話題2の内容そのもの}}

【知らない情報・話してはいけないこと】
- 「知っている情報」と「村の人たち」以外のことは知らない。聞かれたら「分からない」と答える
- ゲームに存在しない場所・人物・アイテムを話に出さない
- 「知っている情報」の内容を変えない
- 自分がAIであることに触れない

【会話のルール】
- 80文字以内の自然な日本語で答える
- {{名前}}らしい口調を保つ
- 深く聞かれた場合も、「知っている情報」と矛盾しない範囲で少し詳しく答えてよい（様子や気持ちを描写する程度）
```

* 【村の人たち】があるので、自由入力で「他に誰がいるの？」と聞かれても、存在しない人を作らずに答えられる
* 【知らない情報】と【会話のルール】は全員同じ文面。各人の部分は5.4・5.5

## 4.6 AIの返答が得られなかったとき

参加者が「壊れた」と感じたり、操作できなくなったりしないようにする。

* **待っている間**：送信したら、会話窓のセリフを「……」にし、操作案内を`返事を待っています…`にする。セリフは`……`→`………`→`…`→`……`…と**0.4秒ごとに点の数を替える**（止まって見えないように。3.3の▼と同じく、画面の動きはこれだけ）。返事（またはエラーの一文）を表示したら止める
  * 時間は`WaitForSecondsRealtime`で数える。ログの`latency_ms`・`ai_wait_total`は変わらない
  * **実装**：`DialogueManager.SubmitTypedText`で`AnimateWaitingText`を始め、`ShowAIResponse`の最初で`StopWaitingAnimation`を呼ぶ
* **時間切れ**：問い合わせは**20秒**で打ち切り、エラーとして扱う（`UnityWebRequest.timeout`）
* **エラーのときの表示**：NPCのセリフ欄に、世界観を壊さない一文を出す（全NPC共通）。かっこ書きのナレーションにして、NPC本人のセリフに見えないようにする
  `（うまく伝わらなかったようだ。もう一度話しかけてみよう）`
* エラーかどうかは、`ChatGPTClient.SendChatMessage`が返す`ChatResult`（`Success`／`Text`／`Error`）で判定する
* **もう一度試す**：エラーのあとEnterを押すと、自由入力の窓に戻る。**失敗した文章が入力欄に残っている**ので、そのまま送信し直せる（成功したら入力欄は空に戻す。「会話をやめる」でも消す）
* **ログ**：`ai_response`の`text`には参加者に表示した一文を、`detail`に失敗の理由を書く（`error=timeout`／`network`／`http_<コード>`／`parse`／`no_key`）。`is_error=1`

# 5. 探索と会話の内容

## 5.1 制限時間

* **5分（300秒）**。説明画面を閉じたときから数え始める（`ExplorationTimer`。`GameManager`のInspectorの`durationSeconds`）
* 数えるのは`play_time`（6.4）と同じゲーム内の時間。**設定パネルを開いている間だけ止まる**（`Time.timeScale = 0`）。会話中・自由入力中・AIの返答待ちの間も進む
* **残り時間の表示**：ミニマップの下に、同じ窓の見た目で`残り 4:32`と出す（`TimerPanel`、3.7）。両条件で同じ
* **残り1分の合図**：残りが60秒以下になったら、`TimerText`の色を漆喰色から真鍮色（`#E0B354`）に変え、その瞬間に1回だけ窓を少し大きくして戻す（1.0→1.15→1.0倍、0.6秒。窓の右上を中心に大きくなる）。音は鳴らさない（時間切れの音（7.4）と区別するため）。設定パネル中は時間が止まっているので、窓の動きも止まる
  * ログには書かない（`explore_start`から240秒後と決まっているので、後から分かる）
  * **実装**：`ExplorationTimer`の`warningSeconds`（60）・`warningColor`・`pulseScale`（1.15）・`pulseDuration`（0.6）。`UpdateWarning`で切り替える

**時間切れのSE**：残り時間が0になった瞬間に1回だけ`TimeUp`のSEを鳴らす（7.4）。会話中でアンケート画面がまだ出ないときも、この時点で鳴らす（時間切れを知らせるため）。BGMはアンケート画面が出るまで鳴り続ける（3.7）

**時間切れのとき**：途中で切らず、今やっていることの区切りまで待ってからアンケート画面にする。ただし新しい会話・新しい選択には進めない。

| 時間切れのときの状態 | アンケート画面になるのは |
|---|---|
| 探索中（`FreeMove`） | すぐ |
| 会話中（`InDialogue`）・選択肢（`InChoice`） | 今のセリフをEnterで閉じた（選択肢を決定した）とき。選んだ先には進まない |
| 自由入力中（`InTyping`） | 「送信」なら、AIの返答を表示してEnterを押したとき。「会話をやめる」ならそのとき |
| AIの返答待ち | 返答を表示してEnterを押したとき |
| 設定パネル（`InSettings`） | （時間が止まっているので起きない） |

* 時間切れのときに`time_up`をログに書く（6.3）。アンケート画面になるまでの超過時間は`session_end`の`play_time`との差で分かる

条件Aの会話の型。条件Bではノード`0`だけを使う（4.2）。**会話はいつも`0`から始まる**（4.4）。1人につき話題を2つ持ち、選択肢でどちらも聞ける。

| id | 内容 | 選択肢・遷移 | 入力 | action |
|---|---|---|---|---|
| 0 | あいさつ（1行） | 少しお話ししてもいいですか？ → 10 ／ いえ、なんでもないです → 90 | | |
| 10 | 「何の話をしようか」など | お仕事は何をされてるんですか？ → 20 ／ 村の人のことを教えてください → 30 | ○（10） | |
| 20 | 話題1の前半 | → 21 | | `topic:1` |
| 21 | 話題1の後半 | 村の人のことも教えてください → 30 ／ ありがとうございました → 99 | ○（21） | |
| 30 | 話題2の前半 | → 31 | | `topic:2` |
| 31 | 話題2の後半 | お仕事のことも聞かせてください → 20 ／ ありがとうございました → 99 | ○（31） | |
| 90 | 「そう、またね」など | 終 | | |
| 99 | 別れのあいさつ | 終 | | |

* 選択肢は1ノード最大2つ（4.2）。CSVの形式（4.4）はクエスト版と同じ。表の「入力」列（`allowInput`）は今は使っていない
* `action`は`topic:<番号>`（話題を聞いた。ログの`topic_heard`）だけを使う
* 話題1（**仕事のこと**）はその人自身の仕事・暮らし、話題2（**村の人のこと**）は別の村人1人の居場所・人柄。話題2で紹介される人は、各セットで6人とも1回ずつになるようにする（誰かの話から次に話す人を見つけられる）
* 選択肢の文は**主人公がNPCに話すことば**（です・ます）で、全員・両セットで同じ。21と31の1つ目は、まだ聞いていない方の話題を名指しして進む（話題1のあとは話題2へ、話題2のあとは話題1へ）。どの選択肢も**16字まで**（選択肢の窓が会話窓の左半分まで伸びないように。3.3）
* 会話は**今いる場所に関係しない話だけ**にする。NPCは自分の店の前にはいないので、店に来た客を迎える言い方（「いらっしゃい」「見ていって」「毎度あり」など）や、目の前の物・匂いを指す話はしない。店や仕事の話をする・食べに来てと誘うのはよい。プロンプトの【会話のルール】にも同じ1行がある（セット1・2の12人）
* 長さもそろえる：どの話題も2ノード、1ノードは60字前後まで（会話窓の3行に収まる）
* 条件Aでは、全員の話題2つずつ（1セット12個）は**すべて選択肢だけで聞ける**（1.3）
* 同じ人に何回話しかけても同じ会話になる（前に聞いた話題を覚えておく仕組みは作らない）

## 5.4 話題セットの中身

セリフの全文はスプレッドシート「NPC会話テキスト」（4.8）、プロンプトの全文はスプレッドシート「NPCプロンプト」（4.7）、話題のつながりと2つのセットの対応表は[`docs/topic-sets.md`](docs/topic-sets.md)。ここでは誰が何を話すかの概要だけを書く。話題2の「→」の先が、その人が紹介する村人（各セットで6人が1つの輪になり、全員が1回ずつ紹介される）。

# 6. 実験ログ（承認・実装済み）

研究の分析に使うデータを、プレイ中に自動でファイルへ記録する（`ExperimentLogger`）。

## 6.1 方針

* **1プレイ（タイトルの「はじめる」〜終了）＝1セッション＝1ファイル**。1行に1つの出来事（イベント）を書く
* セッションの終わりに、集計結果を**1行だけ**`summary.csv`（全セッション共通）に追記する
* 途中でアプリが落ちても記録が残るよう、**1行書くたびにファイルへ書き出す**
* 文字コードはUTF-8（BOM付き）。Excelで開いても文字化けしない
* 参加者は`participantId`（例：P001）だけで識別し、氏名などは記録しない。**自由入力の文章はそのまま記録する**ので、実験の説明・同意書でその旨を伝えること
* プレイヤーの位置（移動の軌跡）は記録しない

## 6.2 保存場所

| 実行のしかた | 保存先 |
|---|---|
| ビルドしたアプリ（実験本番） | アプリ（.exe）と同じフォルダの`ExperimentLogs/` |
| Unityエディタ | `Assets/ExperimentLogs/`（`.gitignore`済み。GitHubには上げない） |

* エディタではUnityがCSVをテキストアセットとして取り込み、`.meta`を作る（ログの中身には影響しない）。`.meta`も`.gitignore`の対象

* ファイル名：`{参加者ID}_{条件}_S{話題セット番号}_{開始日時}.csv`（例：`P001_B_S2_20261012_143005.csv`）
* チュートリアルは同じフォルダに`…_tutorial.csv`（2.4）
* `summary.csv`も同じフォルダ
* 保存先のパスはセッション開始時にConsoleへ`[Log] Session log: …`と出る。タイトル画面の開発者用モーダルの下にも「ログ保存先：…」と表示する

## 6.3 記録するイベント

| event_type | いつ | 主な記録内容 |
|---|---|---|
| `session_start` | MainSceneの開始時 | `detail`にアプリのバージョン・Unityバージョン・AIモデル名・プラットフォーム・何回目のプレイか（`round=1`／`2`。2.5）・どのビルドか（`build=`・`built=`。下の「ビルドの記録」）（参加者ID・条件・話題セットは全行の列に入る） |
| `explore_start` | 説明画面を閉じて探索を始めた（5分の数え始め） | `detail`に制限時間（`duration=300`） |
| `dialogue_start` | NPCに話しかけた | NPC ID・開始ノードID（いつも0） |
| `npc_line` | NPCのセリフが表示された | NPC ID・ノードID・セリフ |
| `topic_heard` | 話題を聞いた（`topic:`のノードを表示した） | NPC ID・ノードID・`detail`に話題番号（`topic`）、それまでに聞いた話題の数（`topics_heard`、同じ話題を2回聞いても1つ）、話しかけたNPCの人数（`npcs_talked`） |
| `choice_select` | 選択肢を決定した | NPC ID・ノードID・選択肢の文・何番目か（条件Aだけ） |
| `free_input_submit` | 自由入力を送信した | NPC ID・ノードID・入力した文章 |
| `ai_response` | AIの返答が表示された | NPC ID・ノードID・返答・応答時間（ミリ秒）・エラーかどうか・プロンプトの識別子 |
| `dialogue_end` | 会話を閉じた | NPC ID・会話時間・この会話での選択回数・自由入力回数。「会話をやめる」で閉じたときは`detail`に`end=quit_button` |
| `time_up` | 5分たった | `detail`にそのときの状態（`state=InChoice`など） |
| `settings_open`／`settings_close` | 設定パネルの開閉 | 閉じたときの音量・感度。`duration`は開いていた**実時間**（パネル表示中は`play_time`が止まるため）。スライダーの細かい動きは記録しない |
| `respawn` | 「初期位置に戻る」を押した | 押す前の位置（`from_x`／`from_z`） |
| `session_end` | セッションの終わり | 終わり方（`time_up`／`back_to_title`／`app_quit`。それ以外でシーンが消えたときは`scene_unloaded`）・総プレイ時間。会話中・設定パネル表示中に終わった場合は、先にその`dialogue_end`／`settings_close`を書く |

* **AIのエラー**：返答が得られなかったら`is_error=1`にし、`detail`に理由（`error=…`）を書く（4.6）。プロンプトが見つからなかったときも`is_error=1`（`detail`は`prompt=none`）
* `npc_line`はノードを表示するたびに書く。条件Bではノード`0`のときだけ
* 条件Bでは`choice_select`・`topic_heard`は出ない（ノード`0`には`topic:`が無いため）。話題を聞けたかは、`free_input_submit`・`ai_response`の文章から後で判定する
* 会話時間（`dialogue_end`の`duration`）・会話ごとの選択回数と自由入力回数は、`ExperimentLogger`が自分で計算して書く
* 時間切れ（`time_up`）からアンケート画面（`session_end`）までの超過時間は、2つの`play_time`の差で分かる
* **プロンプトの識別子**：使った`PromptData`の場所（例：`S1/NPC005`）と、本文のハッシュ値（先頭8文字）。実験期間中にプロンプトが変わっていないかを後から確認できる（1.5）
* **ビルドの記録**：`session_start`の`detail`の最後に`build=724f571;built=20261030_152000`のように入る（チュートリアルのログも同じ）。`build`はビルドしたときのgitのコミット（`git rev-parse --short HEAD`）で、コミットしていない変更があれば後ろに`-dirty`、gitが使えなければ`unknown`。`built`はビルドした日時。エディタでPlayしたときは`build=editor`（`built`なし）。`app=`（Player Settingsのバージョン）は手で上げないと同じままなので、ビルドの区別はこちらで行う
  * 本番は**コミットしてからビルドする**（`-dirty`の付かないビルド）と、`build=`から使ったコード・会話・プロンプトをgitで正確にたどれる。エディタでPlayするとフォント（`NotoSansJP-Regular SDF.asset`）に文字が足されて変更が出ることがあるので、ビルドの前にコミットするか戻す
  * **実装**：エディタ用の`BuildInfoWriter`（`IPreprocessBuildWithReport`）がビルドの前に`Assets/Resources/build_info.txt`を書き、`ExperimentLogger.BuildInfo`が読む（エディタでは読まない）

## 6.4 時間

* `timestamp`：PCの時計の日時（例：`2026-10-12T14:30:05.123`）
* `play_time`：MainSceneを開始してからの秒数（小数3桁）。**設定パネルで時間を止めている間は進まない**（`Time.timeSinceLevelLoad`）。説明画面を出している間は進む（5分の数え始めは`explore_start`の`play_time`）

会話時間・探索時間などは`play_time`の差で計算する。

## 6.5 実装の構成

`ExperimentLogger`（MainSceneの`GameManager`に付けてある）がファイルの作成・書き込み・集計を担当し、他のスクリプトからは`ExperimentLogger.Log(...)`の1行で呼ぶ。AIのモデル名は`ChatGPTClient.ModelName`から読む。

| クラス | 場所 | イベント |
|---|---|---|
| `DialogueManager` | `StartNode`／`ShowNode`／`ExecuteNodeAction`／選択肢の決定／`SubmitTypedText`／`ShowAIResponse`／`CloseDialogue`／`HandleTimeUp`／`OpenSettings`／`CloseSettings`／`RespawnPlayer` | dialogue_start／npc_line／topic_heard／choice_select／free_input_submit／ai_response／dialogue_end／time_up／settings_open／settings_close／respawn |
| `ExplorationTimer` | `Begin` | explore_start |
| `DialogueManager` | 開発者用コマンド`Ctrl+Shift+T`（2.5） | session_end（back_to_title） |
| `DialogueManager` | `EndGame`（アンケート画面） | session_end（time_up） |
| `ExperimentLogger` | 開始時／アプリ終了時（エディタのPlay停止も含む） | session_start／session_end（app_quit） |

## 6.6 イベントログの形式

```csv
session_id,participant_id,condition,set,timestamp,play_time,event_type,npc_id,node_id,text,player_input,choice_index,clue_id,duration,is_error,detail
```

| 列 | 内容 |
|---|---|
| `session_id` | セッションのID（開始日時＋参加者ID） |
| `participant_id`／`condition`／`set` | 全行に入れる（複数ファイルを結合して分析しやすいように）。`set`は話題セット番号 |
| `timestamp`／`play_time` | 6.4 |
| `event_type` | 6.3 |
| `npc_id`／`node_id` | 対象のNPCとノード |
| `text` | NPCのセリフ・選んだ選択肢の文・AIの返答 |
| `player_input` | 自由入力の文章 |
| `choice_index` | 選んだ選択肢の順番（0始まり） |
| `clue_id` | 使っていない（クエスト版の手がかりID。列の並びを変えないよう空欄で残している） |
| `duration` | 会話時間・設定パネルを開いていた時間など（秒） |
| `is_error` | AIのエラーなら1 |
| `detail` | その他（`key=value`を`;`区切り。例：`prompt=S1/NPC005;hash=3fa2c91b;latency_ms=1840`） |

使わない列は空欄。文章にカンマ・改行・`"`が含まれても崩れないよう、`"`で囲む。

## 6.7 集計ファイル（summary.csv）

1セッション1行。

```csv
session_id,participant_id,condition,set,start_time,end_reason,total_play_time,explore_start_time,time_up_time,dialogue_count,choice_count,free_input_count,ai_error_count,ai_wait_total,npcs_talked,topics_heard,settings_open_count,respawn_count,talk_NPC001,talk_NPC002,talk_NPC003,talk_NPC004,talk_NPC005,talk_NPC006
```

* `*_time`：そのイベントが起きた`play_time`（起きなければ空欄）
* `ai_wait_total`：AIの返答待ちの合計秒数（`ai_response`の`latency_ms`の合計）。条件Bでは5分のうちこの分だけ歩く・話す時間が減るので、分析で考慮できるように入れている
* `npcs_talked`：話しかけた人数（0〜6）、`topics_heard`：聞いた話題の数（0〜12）。条件Bでは**空欄**（話題を選択肢で聞かないため。0だと「1つも聞かなかった」と読めてしまう）
* `talk_NPC00x`：そのNPCとの会話の回数と合計時間（例：`3/42.5`＝3回・42.5秒）
* イベントログから計算し直せる内容だが、条件A・Bの比較をすぐできるように用意する
* 既にある`summary.csv`の1行目が今の列と違う（クエスト版のものなど）ときは、`summary_old_{日時}.csv`に名前を変えてから新しく作る（列がずれた行が混ざらないように）
* **`summary.csv`に書けないとき**（実験者がExcelで開いたままにしていてロックされている、など）は、同じフォルダに`summary_pending_{日時}_{参加者ID}.csv`を作り、`summary.csv`と同じ見出し行＋その1行を書く（Consoleに`[Log] summary.csv is locked (…). Wrote … instead`）。行を失わないため
  * `summary.csv`へは**実験者が写す**（自動ではまとめない。ロックが続いているときに、ゲームが勝手に`summary.csv`を書き換えないように）。写したら`summary_pending_…`は消す
  * 残っている間は、開発者用モーダルの「ログ保存」に件数が出る（3.1）
  * **実装**：`ExperimentLogger.AppendSummary`の`catch`で書く

## 7.2 シーン

| シーン | ビルド番号 | 内容 |
|---|---|---|
| `Assets/TitleScene.unity` | 0 | タイトル画面（3.1） |
| `Assets/MainScene.unity` | 1 | 村。`GameManager`オブジェクトに`GameManager`・`DialogueManager`・`ChatGPTClient`・`ExperimentSettings`・`ExplorationTimer`・`AudioVolumeSettings`・`LookSensitivitySettings`・`ExperimentLogger`が付いている |

## 7.3 プレイヤーとカメラ

* 見た目は購入アセットの`Axe_Warrior`を`PlayerArmature`の子として使う。モデルの横位置は回転の中心に合わせてある（`localPosition.x = 0`。ずれていると片足を軸に回っているように見える）
* カメラは`PlayerFollowCamera`（`Cinemachine3rdPersonFollow`）。`CameraSide = 0.5`でキャラクターを画面の中央に映す（0.5〜1にすると右肩越しの視点になる）

## 7.4 音

AudioMixerは使わず、音量を1か所（`AudioVolumeSettings`）で持ち、各`AudioSource`に付けた`VolumeChannel`（BGM／SE）が「元の音量×設定音量」を反映する。

| 種類 | 音源 | 備考 |
|---|---|---|
| BGM | シーンのルートの`BGM`。本番は`Assets/Audio/BGM.wav`（約82秒）、チュートリアルは`Assets/Audio/Tutorial.mp3` | ループ再生・起動時に自動再生・2D。読み込みはStreaming・Vorbis品質70% |
| SE | `Player/PlayerArmature/Audio/`の`Footstep_Concrete`・`Footstep_Land` | 足音・着地音 |
| SE | MainSceneの`GameManager`の子`TimeUpSE`。`Assets/Audio/TimeUp.mp3` | 時間切れの音（5.1）。`ExplorationTimer`が時間切れの瞬間に1回鳴らす。ループなし・起動時に再生しない・2D。読み込みはDecompress On Load |

* 初期値はBGM・SEとも80%。保存しない（1.4）
* 新しい音を足すときは、その`AudioSource`に`VolumeChannel`を付ける

## 7.5 空とライティング

* 空はAsset Storeの無料素材「Simple Sky - Cartoon assets」。シーンのルートの`Sky`の中に、空のドーム（`SkyDome`、村の中心(11, 0, 128)・スケール1.3・半径約430m）とローポリの雲12個（`Clouds`）を置いている。どれも影を落とさない
* ドームと雲には、素材のマテリアルをコピーした`Assets/Material/SimpleSky_Day.mat`（UVオフセット**−0.05**＝明るい昼の青空）を使う。オフセットで時間帯が変わる（0.1付近で夕方寄り、0.2で夕方、0.3以降で夜）。ドームの月（`Moon`）と星（`Stars`）は非表示
* ドームはカメラの描画距離（500m）の内側に収めてある。ドームを大きくしたりカメラのFar Clipを小さくしたりすると空が消える
* スカイボックスは使わない。環境光は3色指定（空 RGB(140,184,242)・地平線 RGB(199,209,219)・地面 RGB(107,115,92)）。太陽（`Directional Light`）は色温度6500K（昼の白い光）
* 焼き込みライティングは使わない（`Assets/Settings/MainSceneLighting.lighting`：Baked GI・Realtime GIともオフ）。環境光のデータは`Assets/MainSceneLight/LightingData.asset`

## 7.6 水に入れないようにする壁

* 水面（`Background/Landscape/Water`、y=−0.9）まで岸の地面がなだらかに続いていて、そのままでは浅瀬に入れてしまう。そこでシーンのルートの`WaterBlockers`に、岸に沿って見えない当たり判定の箱（`Blocker`、697個・高さ6m）を並べている
* 0.5m四方ごとに「水面以外の当たり判定の一番高い所が水面より低いか」を調べ、陸と接している水のマスにだけ置いた。桟橋・岩・ボートは陸として扱うので、桟橋の上は先端まで歩ける
* 箱は`Water`レイヤー。カメラの衝突判定（`Default`のみ）に含まれないので、カメラが押し戻されることはない
* 岸の地形・桟橋・水面の高さを変えたら、Unityのメニュー **Tools → 研究用 → 水の壁を作り直す** で作り直す（`Assets/Editor/SceneBuildTools.cs`）

| もの | 理由 | 別のPCで開くとき |

| `Assets/PurchasedAssets/`（Village・Starter Assets・キャラクター・Simple Skyなど） | 購入アセットなので`.gitignore`で除外 | 同じアセットをインポートして`Assets/PurchasedAssets/`に置く（Simple Skyは`Assets/PurchasedAssets/SimpleSky/`） |

# 9. 開発の進め方

Claude Codeが本仕様書を参照し、Unity MCP経由で開発する。

## 9.1 設計から実装まで

1. 新しい機能・変更は、まずREADMEに設計を書き、見出しに「**案・レビュー待ち**」と付ける（問題・理由・研究への影響も書く）
2. ユーザーが確認・承認する
3. 承認後に実装する（1ファイルずつ）
4. 実装したら、READMEには**今の仕様**（どう動くか・見た目・実装の構成）だけを残し、問題・理由・研究への影響・確認結果は[`docs/history.md`](docs/history.md)に日付を付けて移す
5. セリフ・プロンプトはスプレッドシートを直してから取り込む（4.8・4.7）。話題（誰が誰を紹介するか）を変えたときは[`docs/topic-sets.md`](docs/topic-sets.md)の対応表も直す

## 9.2 基本ルール

* 既存の実装を確認してから変更する。推測だけでUnityの状態を判断せず、Unity MCPで確認する
* 不要な既存機能を削除しない。既存のクラスの役割を尊重する
* 1回の変更で大量のファイルを変更しない
* 変更したらUnityでコンパイルし、Consoleのエラーを確認する。エラーがあれば直してから次へ進む
* 研究仕様（1.6）は勝手に変えない
