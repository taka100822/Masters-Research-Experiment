# 1. 研究と実験

## 1.1 目的

修士研究「生成AIを用いた自由入力機能の導入が、プレイヤーの対話行動およびゲーム体験に与える影響」のための研究用RPGプロトタイプ。プレイヤーは小さな村を**5分間自由に探索し**、村人と話す。NPCとの**対話方式の違い**がプレイヤーの対話行動とゲーム体験に与える影響を比較する。

## 1.2 実験条件

| 条件 | 対話方式 |
|---|---|
| **A：選択肢のみ** | ゲーム側が用意した選択肢からプレイヤーが発言を選ぶ |
| **B：選択肢＋自由入力** | Aと同じ選択肢に加え、決められた場面で「入力する」を選ぶと文章を入力でき、生成AIがNPCとして返答する |

* 条件は話題セットやNPCに結び付けず、「参加者が今どちらの条件で遊んでいるか」という**全体設定**として持つ。同じNPC・同じ話題セットでも、条件Aでは選択肢だけ、条件Bでは同じ場面に「入力する」が加わる
* 設定は実験者がタイトル画面の開発者用モーダルで行う（3.1）。実装上は「`allowInput=1`のノード、かつ条件B」のときだけ「入力する」が出る（4.2）

## 1.3 話題セットとカウンターバランス

参加者は条件A・Bの両方を遊ぶ。同じ村人と同じ話を2回すると2回目は新しさがなくなるので、**構成をそろえた話題セットを2つ**用意する（5章）。

* 話題セット1：商人ヴィクター・村人ルカ・薬師ティム・村長ニコラ・鍛冶屋ヤニス・料理人ステフ
* 話題セット2：大工シャック・先生ディルク・パン屋マヌ・布屋パウ・地主マイケル・漁師カワイ

話題セットと条件を固定のペアにすると、体験の違いが対話方式によるのか話題の内容によるのか区別できない。そのため話題セットと条件は独立させ、参加者を次の4グループに均等に振り分ける。

1. 条件A×セット1 → 条件B×セット2
2. 条件A×セット2 → 条件B×セット1
3. 条件B×セット1 → 条件A×セット2
4. 条件B×セット2 → 条件A×セット1

* 2つのセットで同じにするもの：村・NPCの人数と位置・会話の型（5.3）・話題の数と長さ・自由入力の場面
* 違うもの：村人の名前・性格・話題・衣装（5.2）
* 村の地形は2回目には覚えているが、順番を入れ替えているので条件の差にはならない

**大前提**：全員の話題2つずつ（1セット12個）は**すべて選択肢だけで聞ける**。自由入力は話を掘り下げる追加の手段で、聞ける話題の数は両条件で同じ。

## 1.4 条件以外の差を小さくする

ゲームとしての面白さより、実験条件の統制を優先する。マップ・NPCの配置・会話の型と話題の量・制限時間・UI・操作・BGM/SE・グラフィックは、両条件・両セットで同じにする。主な違いは対話方式だけにする。

* 2つの話題セットの対応は5.6、会話の型の統一は5.3
* ミニマップ・NPCの名前表示・残り時間・説明画面の文は、両条件・両セットで同じように出る
* 音量・視点感度は**保存せず、起動するたびに初期値に戻す**（前の参加者の設定が次の参加者に引き継がれないように）

## 1.5 研究データの再現性

Unityバージョン・AIモデル・API仕様・NPCプロンプト・会話データ（話題セット）・ゲームバージョン・実験日時・実験条件を固定し、記録する。特に条件Bでは、**実験期間中にプロンプトやモデルを変更しない**。ログには使ったプロンプトの識別子とハッシュ値を残して、後から確認できるようにする（6章）。

## 1.6 研究仕様の変更ルール

次のものは勝手に変更しない：実験条件、NPCの知識（話題）、制限時間、ログ項目、AIモデル、AIプロンプト、会話方式。変更が必要なときは、まず変更内容と研究上の影響を説明する。

## 1.7 課題の変更：クエストから自由探索へ（2026-10-09 承認・実装済み）

最初は「依頼を受けて手がかりを集めるクエスト」で比較する作りだったが、2026-10-09に「村を5分間自由に探索する」課題に変えた（ブランチ`feature/Exploring-city`）。クエスト版の実装と仕様は`main`ブランチとgitの履歴（コミット`36a2b1b`まで）に残っているので、戻すときはそこから。クエスト用のクラス・データはファイルとしては残してある（8章）。

| | クエスト版 | 自由探索版（今） |
|---|---|---|
| 課題 | 依頼を受け、手がかり4つを集めて依頼人に報告 | 村を自由に歩き、村人と話す。達成条件はない |
| 終わり方 | 依頼人への報告で達成 | **5分たったら**終わる |
| プレイ時間 | 10〜20分（人によって違う） | 5分（全員同じ） |
| 実験条件 | A：選択肢のみ／B：選択肢＋自由入力 | 同じ |
| 2回分の内容 | クエスト1「消えた薬草」・クエスト2「祭りの道具探し」 | 話題セット1・2 |
| 自由入力の場面 | 1クエストにつき4か所 | 1人3か所×6人 |
| 画面右上 | ミニマップ＋チェックリスト | ミニマップ＋残り時間 |

### 決めたこと

| 内容 | 決定 |
|---|---|
| セット2の村人 | **別人**にする（同じ人が2回目に別の話をすると、あいさつから不自然になる） |
| 残り時間の表示 | **出す**（いつ終わるか分からない不安で行動が変わるのを避ける。両条件で同じ） |
| AIの返答待ちの間のタイマー | **止めない**（返答を待つことも条件Bの体験の一部。待ち時間はログで把握する） |
| 時間切れの扱い | 今のやりとりの区切りまで待つ（5.1） |
| 1人あたりの話題 | 2つ。どの話題も2ノード（5.3）。5分で6人全員と全部話すには少し足りない量にして、誰と話すかを選ぶ余地を残す |

### 研究への影響

| 変更 | 影響 |
|---|---|
| 課題をクエストから自由探索に | 手がかり・達成条件がなくなり、誰と・どれだけ話すかが参加者に任される。対話行動の指標は、会話の回数・時間、話しかけた人数、聞いた話題の数、自由入力の回数と内容になる。「達成までの時間」は測れなくなる |
| 時間を5分に固定 | プレイ時間が全員・両条件でそろう。一方、条件Bでは返答待ちの時間も5分に含まれるので、その分ほかのことをする時間が減る（summary.csvの`ai_wait_total`で把握する） |
| 2つ目の内容（話題セット） | クエスト1・2の代わり。構成をそろえ、カウンターバランスで内容の差を相殺する |
| 自由入力の場面が増える | 1クエスト4か所 → 全員に1人3か所。自由入力を使える機会が増える |
| 会話データ・プロンプトを作り直した | プロンプトのハッシュ値は全部変わった（本番の実験より前の変更なので、実験データへの影響はない） |
| ログ項目 | 6章のとおり変えた（クエストのイベントをなくし、探索開始・話題・時間切れを足した） |

# 2. ゲームの概要

## 2.1 規模

* ジャンル：小規模な探索型RPG（戦闘・成長システム・クエストなし）
* プレイ時間：探索5分（＋説明画面）
* マップ：村1つ（`Assets/MainScene.unity`、購入アセットのVillageを使用）
* NPC：6人。話題セットごとに名前・性格・話題・衣装が変わる（5.2）
* 話題セット：2つ。1回のプレイでは設定で選んだ1つだけを使う
* セーブ：なし（1回のプレイを最初から最後まで行う）

## 2.2 ゲームの流れ

```text
タイトル画面（実験者が開発者用モーダルで参加者ID・条件・話題セットを設定）
 ↓ はじめる
説明画面（村の上で、操作できない状態で表示。3.5）
 ↓ Enter
探索（5分）：自由に歩き、好きな村人と好きなだけ話す
 ↓ 5分たつ（会話中なら、その会話の区切りまで待つ。5.1）
終了画面（操作不可）
```

プレイ中はいつでも`Q`で設定パネルを開ける（探索中のみ）。設定パネルを開いている間は残り時間も止まる。設定パネルから「タイトルへ戻る」と、進み具合（残り時間を含む）はリセットされる。

## 2.3 操作

| キー | 操作 |
|---|---|
| WASD | 移動 |
| マウス | カメラ操作 |
| Space | ジャンプ |
| Enter | 説明画面を閉じる／話しかける／会話を進める／選択肢を決定する |
| ↑ ↓ | 選択肢を選ぶ |
| Q | 設定パネルを開く・閉じる（探索中のみ） |
| マウスクリック | 自由入力の「送信」（空欄では押せない）・「やめる」（選択肢に戻る）ボタン・設定パネル・タイトル画面の操作 |

移動・カメラは Starter Assets Third Person Controller（購入アセット）の標準入力。会話まわりの入力は`DialogueManager`が`Keyboard.current`を直接見ている。

# 3. 画面とUI

## 3.1 タイトル画面

ゲームを起動すると最初に出る画面（`Assets/TitleScene.unity`、ビルド設定の0番）。

見た目・配置の詳細は3.8。

```text
┌──────────────────────────────────────┐
│                                      │
│        研 究 用 ゲ ー ム              │  ← 大きなタイトル文字（TitleText）
│                                      │
│           [  はじめる  ]              │
│                                      │
│ P000・A・S1              [開発者用]    │  ← 現在の実験設定（実験者の確認用・目立たない表示）
└──────────────────────────────────────┘
```

* **はじめる**：MainSceneへ移る
* **開発者用**：開発者用モーダルを開く
* 背景は村の全景をぼかした画像（`Assets/Texture/title_background_blur.png`。元画像`title_background.png`にガウスぼかし半径12px）に黒25%の暗幕を重ねたもの
* 設定表示は`参加者ID・条件・S話題セット番号`の短い形で、「条件」という言葉は出さない（参加者が自分の条件を意識しにくくするため）
* タイトル画面ではカーソルを表示する

**開発者用モーダル**

```text
┌────────────────────────────────┐
│ 開発者用設定                      │
│ 参加者ID   [ P000            ]   │
│ 対話条件   [ A：選択肢のみ    ▼]  │  ← A：選択肢のみ／B：選択肢＋自由入力
│ 話題セット [ 1：セット1       ▼]  │  ← 1：セット1／2：セット2
│ ログ保存先：…                     │
│          [ キャンセル ] [ 決定 ]   │
└────────────────────────────────┘
```

* 「決定」で値を反映し、タイトルの設定表示も更新する。参加者IDが空なら閉じられない（「参加者IDを入力してください」）
* 「キャンセル」で値を変えずに閉じる。次に開いたときは`ExperimentConfig`の値が入り直す
* 開いている間はタイトル文字と「はじめる」を隠す（窓の後ろからはみ出して見えないように）
* 話題セットのドロップダウンのGameObject名は、クエスト版のまま`QuestDropdown`

**設定の受け渡し**

* タイトルで設定した値はstaticな`ExperimentConfig`（`ParticipantId`・`Condition`・`TopicSet`）に置き、MainSceneの`ExperimentSettings`が起動時（`Awake`）に読む。読んだ値はConsoleに`[Experiment] participant=… condition=… set=…`と出る
* エディタでMainSceneを直接Playしたときは、`ExperimentSettings`のInspectorの値を使う
* ファイルには保存しない。アプリを起動し直すと初期値（P000／条件A／セット1）に戻る

```text

├── QuestCompletePanel      終了画面（3.5。名前はクエスト版のまま）
```

見た目・配置の詳細は3.7。

```text
                              ┌────────────┐
                              │▶ 仕事のこと  │
                              │  村の人のこと │
                              │  入力する    │ ← 条件Bかつ allowInput=1 のノードのみ
                              └────────────┘
 ╔══════════╗
┌╨薬師ティム╨─────────────────────────┐ ← 名前は吊り看板（displayName）
```

* 会話中はプレイヤーの移動・カメラ操作を止める
* 自由入力中も会話ウィンドウ（直前のセリフ）は表示したまま、その上に入力欄と「やめる」「送信」ボタンを出す
* 近くのNPCがいると`TalkHint`（画面下中央、`[Enter] ○○と話す`）とNPC頭上の吹き出し（3.3）の両方が出る

## 3.3 NPCの頭上UI

各NPCの`HeadUI/Canvas`（ワールド空間。`Billboard`で常にカメラの方を向く）に次の2つがある。下から 頭 → 名前 → 吹き出し の順に並ぶ。

* **名前**（`NameLabel`）：常に表示。`NPCDialogue.DisplayName`（今の話題セットの名前。5.2）を起動時に`NPCInteraction`が入れる。白文字＋黒縁（`NotoSansJP-Regular SDF - NameOutline.mat`）。建物の陰では隠れる
* **吹き出し**（`Image`）：プレイヤーが近づいて会話できる範囲に入ったときだけ表示
* 全員同じ色。クエスト版にあった「依頼人だけ名前と吹き出しを金色にする」仕組み（`NPCInteraction.clientColor`・`IsQuestClient()`）はコードに残っているが、`QuestManager`がシーンに無いので働かない

## 3.4 ミニマップ

画面右上（170×170px）に、プレイヤーを中心にした地図を常に表示する。

* 地図はエディタで村の真上から1回だけ撮影した静止画（`Assets/Texture/minimap_village.png`、中心(11, 128)・一辺128m）。実行中は表示範囲（`RawImage.uvRect`）を動かしてスクロールさせる
* プレイヤーの周り一辺30mを表示。**北が上で固定**し、プレイヤーの三角アイコンが向きを指す

| 対象 | 形 | 色 |
|---|---|---|
| プレイヤー | 三角（`minimap_arrow.png`） | 水色 |
| NPC | 丸（Unity標準の`Knob`） | 白 |

* 表示範囲の外のNPCは隠す（クエスト版では依頼人だけ大きい金色の丸で縁に止めていた。仕組みは`MinimapUI`に残っているが、依頼人がいないので出ない）
* NPCの配置や建物を変えたら、Unityのメニュー **Tools → 研究用 → ミニマップの地図を撮り直す** で撮り直す（撮影範囲は`MinimapUI`の`mapWorldCenter`／`mapWorldSize`から自動で読む。NPCとプレイヤーは写らない）

## 3.5 説明画面・残り時間・終了画面

**説明画面**（`IntroPanel`）：MainSceneに入ると、画面全体の暗幕（黒50%）の上に、会話窓と同じ見た目（樫色＋真鍮の縁、640×260）の窓を中央に出す。この間は動けない（`GameState.Intro`）。Enterで閉じると、5分を数え始める（5.1）。両条件・両セットで同じ文で、条件Bの「入力する」には触れない（操作は実験者が事前に口頭で説明する）。

```text
これから5分間、村の中を自由に歩いて、
村の人たちと話してみてください。
時間になったら自動で終わります。

              [Enter] はじめる
```

**残り時間**（`TimerPanel` > `TimerText`）：ミニマップの下（クエスト版のチェックリストの所）に、同じ窓の見た目（170×48）で`残り 4:33`と出す。秒は切り上げ（残り4:32.4なら4:33）。説明画面を閉じたときに表示される。

**終了画面**（`QuestCompletePanel`）：時間切れのあと（5.1）、全画面に「時間になりました　お疲れさまでした。実験者の指示があるまでお待ちください。」を表示する。以後は移動・会話とも操作不可（`GameState.Ended`）。BGMは鳴り続ける。

## 3.6 設定パネル

探索中に`Q`で開き、`Q`または「閉じる」ボタンで閉じる（`Esc`は使わない）。見た目・配置の詳細は3.9。

```text
┌──────────────────────────────────────┐
│ 設定                                  │
│ 音楽        ━━━━━━━━━━●━━━   80%      │
│ 効果音      ━━━━━━━━━━●━━━   80%      │
│ 視点の速さ  ━━━━●━━━━━━━━━   1.0      │
│ [ 初期位置に戻る ] [ タイトルへ戻る ]  │
│ 動けなくなったときは「初期位置に戻る」   │
│                       [ 閉じる [Q] ]  │
└──────────────────────────────────────┘
```

* **開けるのは探索中だけ**。説明画面・会話中・選択肢中・自由入力中・終了画面では開かない（自由入力で「q」を打っても開かないように）
* 開いている間は**ゲーム内の時間を止める**（`Time.timeScale = 0`）。残り時間も止まる。音は止めない（スライダーを動かしながら音量を確かめられるように）。カーソルを表示し、プレイヤー操作を止める
* **音楽・効果音**（コード・ログ上はBGM・SE）：0〜100%、初期値80%（7.4）
* **視点の速さ**（コード・ログ上は感度）：視点を回す速さの倍率。0.2〜3.0、初期値1.0。`LookSensitivitySettings`が`PlayerInput`のLookアクションに、元のプロセッサ（マウス×0.05など）の後ろへ`ScaleVector2(x=感度,y=感度)`を実行中だけ追加する（購入アセットの入力設定は変更しない）
* **タイトルへ戻る**：確認（「タイトルへ戻ると、ここまでの進み具合は消えます。」）で「タイトルへ戻る」を押すと、TitleSceneへ戻る（残り時間も含めて最初から）。「キャンセル」で元に戻る（3.9）
* **初期位置に戻る**：ゲーム開始時の位置・向きへ瞬間移動し、パネルを閉じる。建物の隙間にはまったときなどの救済用。残り時間はそのまま。カメラが村の上空を横切らないよう、Cinemachineに瞬間移動を伝えている（`OnTargetObjectWarped`）

## 3.10 会話の本文の改行（承認・実装済み）

10.1 Phase 9「UI調整」の一部（2026-10-05 実装）。下の例のセリフはクエスト版のもの。

### 問題（2026-10-05）

会話の本文（`DialogueText`）の改行位置がばらばらで読みにくい。TextMeshProは日本語を**1文字ごとにどこでも**折り返す（句読点の行頭禁止だけは守る）ので、窓の右端に来た文字で機械的に改行され、単語の途中で切れる。

```text
村に届く荷物は、いつも村の入り口に置かれるんだ。薬草の包
みもきっとあそこに置かれたはずだよ。
```

CSVのセリフに手で改行を入れても、AIの返答（条件B）は長さも内容も毎回違うので直せない。

### 方針：文節で折り返す

* 本文を**文節**（「薬草の」「包みも」「きっと」…）に区切り、**文節の途中では改行しない**ようにする。改行は文節と文節の間だけで起きる
* 区切りは**BudouX**（Googleの日本語改行用ライブラリ。Chromeの`word-break: auto-phrase`にも使われている。Apache 2.0）の日本語モデルを使う。辞書を持たない小さな学習済みモデル（JSON 1つ）で、C#に移すのは数十行
* CSVのセリフにもAIの返答にも、**表示の直前に同じ処理**をかける。会話データ・プロンプトは書き換えない

```text
村に届く荷物は、いつも村の入り口に置かれるんだ。薬草の
包みもきっとあそこに置かれたはずだよ。
```

**しくみ**：文節ごとに`<nobr>…</nobr>`（TMPの改行禁止タグ）で囲み、文節の間に幅ゼロの空白（U+200B）を入れて改行してよい位置にする。1つの文節が1行より長いとき（ほぼない）は、TMPがふつうに途中で折り返す。

* 対象：NPCのセリフ（`ShowNode`）とAIの返答（`ShowAIResponse`）。選択肢・名前・操作案内は短いので変えない
* `<`などTMPのタグと紛らわしい文字がAIの返答に入っていても壊れないよう、元の文のタグはそのまま残し、タグの中は区切らない
* 手で入れた改行（CSVの`\n`など）はそのまま残す

### 研究への影響（1.6）

| 変更 | 影響 | 判断 |
|---|---|---|
| 本文の改行位置 | 見た目だけ。両条件・両セットで同じ処理。文の中身は変わらない | 問題なし。2026-10-05 承認 |
| ログ | `npc_line`・`ai_response`には**区切る前の元の文**を書く（タグを混ぜない）。ログ項目は変えない | 問題なし |

### 実装の構成

* `Assets/Resources/BudouX/ja.json`：BudouXの日本語モデル（GitHub `google/budoux`から取得。ライセンス表記を同じフォルダに置く）
* `JapaneseLineBreaker`（新規・静的クラス）：`Format(string text)`で文節ごとに`<nobr>`で囲んだ文を返す。モデルは最初の1回だけ読む。読めなければ元の文をそのまま返す（今と同じ表示）
* `DialogueManager`：`dialogueText.text = ...`の2か所（`ShowNode`・`ShowAIResponse`）で`JapaneseLineBreaker.Format`を通す
* 確認（2026-10-05、Unity上で会話窓と同じ幅888px・24pxのTMPに表示）：会話データの全56行のうち折り返す12行すべてで、改行は文節の間だけで起きた（文節の途中での改行0件、行数は増えず最大2行）。`NotoSansJP-Regular SDF`はU+200Bを持つので□にならない
* BudouXの区切りが辞書の単語と合わないことはある（例：「すれ違った」が「すれ／違った」に分かれる）。そのときもその区切りの間で改行されるだけで、1文字ずつの折り返しよりは読みやすい

### 追加：入るなら文の終わり（「。」「！」「？」）の後で改行する（承認・実装済み）

文節で折り返すだけだと、1つの行に前の文の終わりと次の文の始まりが並び、文の区切りが目で追いにくい。窓に収まるときは、**文の終わりの後で改行**して1文ずつ行を分ける。

**決まり**

* 本文の途中にある文の終わり（`。！？!?`）の後ろを改行の候補にする。「！？」のように続くときはまとめて1つの終わりとし、直後に`」』）)`が続くときはその後ろ。本文の最後の終わりは候補にしない
* 前の候補から順に、そこで改行しても**本文が3行（窓に入る行数）以内に収まるときだけ**改行する。収まらない候補は飛ばす（文節での折り返しはそのまま）
* 行数はその場で`DialogueText`に並べて数える（窓の幅・文字の大きさを変えても正しく働く）。数えられないときは改行を足さない
* CSVのセリフにもAIの返答にも同じ決まりをかける。AIの返答がもともと3行を超えるときは改行を足さない

**全セリフに当てた結果**（Unity上、幅888px・24px）：途中に文の終わりがある39行（候補43か所）すべてで改行が入り、3行を超えたものはない。

```text
村に届く荷物は、いつも村の入り口に置かれるんだ。
薬草の包みもきっとあそこに置かれたはずだよ。

ありがとう！
村の人に聞いて回ってくれ。
何か分かったら知らせてほしい。

準備を始めたのは3日前だよ。
灯篭もその日に片付けたはずだけど、僕は飾りつけの係だったから、どこへ
運んだかは知らないんだ。
```

**研究への影響（1.6）**：見た目だけ。両条件・両セットで同じ決まり。文の中身・ログ（元の文を書く）は変わらない。

**実装の構成**

* `JapaneseLineBreaker`：`Format(string text, TMP_Text target, int maxLines)`を足す。文の終わりの候補ごとに改行を入れた文を`target.GetTextInfo`で数え、`maxLines`以内なら残す。最後に今の文節の処理をかけて返す
* `DialogueManager`：Inspectorに`maxDialogueLines`（初期値3）。本文を出す2か所で新しい`Format`を使う（パネルを表示してから数える）
* 確認（2026-10-05）：全セリフ56行のうち39行で文の終わりの後に改行が入り、3行を超えたもの・文節の途中での改行は0件。プレイモードの会話窓（`DialogueText`）でも同じく表示された
* 候補は前から順に使うので、文の多い長い返答（主にAI）では、前の文で行を使い切り、後ろの文どうしが同じ行に並ぶことがある（3行に収めるのを優先する）

# 4. 会話システム

## 4.1 状態

`GameState`（`Assets/Script/GameState.cs`）。状態を持ち、遷移させているのは`DialogueManager`（`currentState`）。

| 状態 | 内容 |
|---|---|
| `Intro` | 説明画面（3.5）。Enterで閉じて`FreeMove`へ |
| `FreeMove` | 探索中。移動・カメラ操作ができる。近くにNPCがいればEnterで話しかけられる。Qで設定パネル |
| `InDialogue` | 会話中（選択肢なし）。Enterで次へ |
| `InChoice` | 選択肢を選んでいる。↑↓で移動、Enterで決定 |
| `InTyping` | 自由入力中。送信はボタンのみ（IME変換中のEnterで誤送信しないよう、Enterでは送らない）。「やめる」ボタンで同じノードの選択肢（`InChoice`）に戻る。AIの返答待ちの間もこの状態 |
| `Ended` | 時間切れ後の終了画面。操作不可 |
| `InSettings` | 設定パネル表示中。時間停止 |

プレイヤーを止めるときは必ず`DialogueManager.StopPlayer()`を通す。`ThirdPersonController`を無効にするだけでは、走りながら話しかけたときに走りモーションと足音（アニメーションイベント）が続いてしまうため、速度を0にする`StopMotion()`も呼ぶ（7.3）。

## 4.2 会話の進み方

会話は会話データ（CSV）の**ノード**を順にたどる（4.4）。

* 1ノードの選択肢は最大3つ：`choiceA`、`choiceB`（それぞれ空でなければ表示）、「入力する」（`allowInput=1`かつ条件Bのときだけ自動で追加）
* 選択肢が1つも無いノードでは「次へ」の案内だけを出し、Enterで`nextId`へ進む。`nextId=-1`なら会話を終える
* 「なんでもない」「じゃあね」のような選択肢は、`choiceA`／`choiceB`の文として書き、遷移先に終了用のノードを置く
* 時間切れのあとは、次のノード・選んだ先へは進まず、会話を閉じて終了画面にする（5.1）

## 4.3 自由入力とAIの返答

```text
「入力する」を選ぶ → 入力欄を表示（カーソル表示・移動停止）
 ↓ 送信ボタン
AIへ送信（返答を待つ間もプレイヤーは動けない）
 ↓
AIの返答をNPCのセリフとして表示
 ↓ Enter
「入力する」を選んだノードの nextId へ進む（-1なら会話終了）
```

* AIの返答のあとに進む先は、自由入力を始めた**元のノードの`nextId`**
* 自由入力を出すノードは、`nextId`を**自分自身のID**にしている（5.3）。返答のあとEnterで同じノード（同じ選択肢＋「入力する」）に戻るので、何回でも続けて質問でき、「じゃあね」などの選択肢で会話を終えられる
* AIは会話の履歴を持たない（毎回、システムプロンプト＋今回の入力だけを送る）

## 4.4 会話データ（CSV）

`Assets/Resources/dialogue/S{話題セット番号}/`に、NPC1人につき1つのCSV（`{npcId}.csv`）を置く（`DialogueDatabase`が、会話を始めるときに読み込む）。

```text
id, text, nextId, choiceA, choiceA_next, choiceB, choiceB_next, allowInput, action
```

| 列 | 内容 |
|---|---|
| `id` | ノードID |
| `text` | NPCのセリフ（**半角カンマは使えない**。読点「、」を使う） |
| `nextId` | 選択肢が無いときの次のノード（`-1`で終了） |
| `choiceA`／`choiceA_next`、`choiceB`／`choiceB_next` | 選択肢の文と遷移先 |
| `allowInput` | `1`なら条件Bで「入力する」を出す（列が無いCSVは0扱い） |
| `action` | ノードを表示した瞬間に実行する：`topic:<番号>`（話題を聞いた。ログの`topic_heard`）。空なら何もしない |

* **会話はいつもノード`0`から始まる**（前に聞いた話題を覚えておく仕組みはない）
* 読み込む場所は`Dialogue/S{話題セット番号}/{csvFileName}`だけ。クエスト版の`Q1/`・`Q2/`・`Common/`のCSVは残してあるが読まない
* クエスト版の`action`（`startQuest`／`clue:`／`complete`）はもう使わない（書くとConsoleに警告が出るだけ）

## 4.5 生成AI

* **API**：OpenAI Chat Completions API（`https://api.openai.com/v1/chat/completions`）に`UnityWebRequest`で送る（`ChatGPTClient`）。`ChatGPTClient`は通信だけを担当し、UIやプレイヤー操作には触れない
* **APIキー**：`Assets/Resources/openai_key.txt`から読む（`.gitignore`済み。GitHubには上げない）
* **モデル**：`ChatGPTClient.cs`の定数`model = "gpt-5.6-luna"`（2026-10-05に動作確認済み）。実験期間中は変えない（1.5）
* **プロンプトの読み込み**：`PromptData/S{話題セット番号}/{npcId}` → `NPCDialogue.promptData` の順に探す（`DialogueManager.LoadPromptData()`）。どれも無ければ送信せず、NPCのセリフとして「……（今は話せないようだ）」を表示してConsoleにエラーを出す
* **プロンプトの形式**：`PromptData`（ScriptableObject）の`systemPrompt`という1つの文字列。名前・性格・知っている情報などは、下のテンプレートに沿って文章の中に書く。全員（1セット6人×2セット＝12個）にある
* **エラー**：通信の失敗・時間切れ（20秒）・返答の解析失敗・APIキーが無い、のどれでもゲームは止まらず、参加者向けの一文を表示する（4.6）

**AIに守らせること**（プロンプトの文面で守らせる。コード側での検査はしていない）

* NPCの設定から外れない。存在しない人物・場所・アイテムを作らない
* 「知っている情報」の内容を変えない
* ゲーム外の情報を出さない。自分がAIであることに触れない
* 80文字以内の日本語で答える

**プロンプトのテンプレート**

```text
あなたは村に住む{{役職}}の{{名前}}です。

【性格】
{{一言で表せる人物像}}

【背景】
{{今何をしているか}}

【村の人たち】
{{そのセットの6人の名前・仕事・居場所（セット内で全員同じ文）}}

【知っている情報】
{{話題1・話題2の内容そのもの}}

【知らない情報・話してはいけないこと】
- 「知っている情報」と「村の人たち」以外のことは知らない。聞かれたら「分からない」と答える
- ゲームに存在しない場所・人物・アイテムを話に出さない
- 「知っている情報」の内容を変えない
- 自分がAIであることに触れない

【会話のルール】
- 80文字以内の自然な日本語で答える
- {{名前}}らしい口調を保つ
- 深く聞かれた場合も、「知っている情報」と矛盾しない範囲で少し詳しく答えてよい（様子や気持ちを描写する程度）
```

* 【村の人たち】があるので、自由入力で「他に誰がいるの？」と聞かれても、存在しない人を作らずに答えられる
* 【知らない情報】と【会話のルール】は全員同じ文面。各人の部分は5.4・5.5

## 4.6 AIの返答が得られなかったとき（承認・実装済み）

参加者が「壊れた」と感じたり、操作できなくなったりしないようにする。

**待っている間**
* 送信したら、会話ウィンドウのセリフを「……」にして、返答を待っていることが分かるようにする（今は直前のセリフが出たまま止まって見える）

**時間切れ**
* 今は問い合わせに制限時間が無く、通信が固まると参加者がずっと待たされて操作できなくなる。**20秒**で打ち切り、エラーとして扱う（`UnityWebRequest.timeout`）

**エラーのときの表示**
* 「エラー」の代わりに、世界観を壊さない一文をNPCのセリフ欄に出す：
  `（うまく伝わらなかったようだ。もう一度話しかけてみよう）`
  （かっこ書きのナレーションにして、NPC本人のセリフに見えないようにする。全NPC共通）
* エラーかどうかは、`ChatGPTClient.SendChatMessage`が返す`ChatResult`（`Success`／`Text`／`Error`）で判定する。「エラー」という文字列はもう返さない

**もう一度試す**
* エラーのあとEnterを押すと、これまでどおり同じノードの選択肢（「入力する」を含む）に戻る（5.3の`nextId`＝自分自身の仕組み）
* そこで「入力する」を選ぶと、**失敗した文章が入力欄に残っている**ので、そのまま送信し直せる（成功したら入力欄は空に戻す）

**ログ**
* `ai_response`の`text`には参加者に表示した一文を、`detail`に失敗の理由を書く（`error=timeout`／`network`／`http_<コード>`／`parse`／`no_key`）。`is_error=1`は今までどおり

# 5. 探索と会話の内容

## 5.1 制限時間

* **5分（300秒）**。説明画面を閉じたときから数え始める（`ExplorationTimer`。`GameManager`のInspectorの`durationSeconds`）
* 数えるのは`play_time`（6.4）と同じゲーム内の時間。**設定パネルを開いている間だけ止まる**（`Time.timeScale = 0`）。会話中・自由入力中・AIの返答待ちの間も進む
* **残り時間の表示**：チェックリストがあった所（ミニマップの下）に、同じ窓の見た目で`残り 4:32`と出す（`TimerPanel`、3.5）。両条件で同じ

**時間切れのとき**：途中で切らず、今やっていることの区切りまで待ってから終了画面にする。ただし新しい会話・新しい選択には進めない。

| 時間切れのときの状態 | 終了画面になるのは |
|---|---|
| 探索中（`FreeMove`） | すぐ |
| 会話中（`InDialogue`）・選択肢（`InChoice`） | 今のセリフをEnterで閉じた（選択肢を決定した）とき。選んだ先には進まない |
| 自由入力中（`InTyping`） | 「送信」なら、AIの返答を表示してEnterを押したとき。「やめる」ならそのとき |
| AIの返答待ち | 返答を表示してEnterを押したとき |
| 設定パネル（`InSettings`） | （時間が止まっているので起きない） |

* 時間切れのときに`time_up`をログに書く（6.3）。終了画面になるまでの超過時間は`session_end`の`play_time`との差で分かる

## 5.2 NPC一覧

`npcId`は**位置の番号**（ログ・ファイル名用の固定ID）で、両セットで同じ。名前（`displayName`）・性格・話題・衣装はセットごとに変わる。6人全員を両セットで同じ位置に置く。

| npcId | 位置 (x, z) | セット1 | セット2 |
|---|---|---|---|

## 5.3 会話の型（全NPC・両セット共通）

**会話はいつも`0`から始まる**（4.4）。1人につき話題を2つ持ち、選択肢でどちらも聞ける。

| id | 内容 | 選択肢・遷移 | 入力 | action |
|---|---|---|---|---|
| 0 | あいさつ（1行） | 話を聞く → 10 ／ なんでもない → 90 | | |
| 10 | 「何の話をしようか」など | 仕事のこと → 20 ／ 村の人のこと → 30 | ○（10） | |
| 20 | 話題1の前半 | → 21 | | `topic:1` |
| 21 | 話題1の後半 | ほかの話も聞く → 30 ／ じゃあね → 99 | ○（21） | |
| 30 | 話題2の前半 | → 31 | | `topic:2` |
| 31 | 話題2の後半 | ほかの話も聞く → 20 ／ じゃあね → 99 | ○（31） | |
| 90 | 「そう、またね」など | 終 | | |
| 99 | 別れのあいさつ | 終 | | |

* 選択肢は1ノード最大2つ＋「入力する」（4.2）。CSVの形式（4.4）はクエスト版と同じ
* `action`は`topic:<番号>`（話題を聞いた。ログの`topic_heard`）だけを使う
* 話題1（**仕事のこと**）はその人自身の仕事・暮らし、話題2（**村の人のこと**）は別の村人1人の居場所・人柄。話題2で紹介される人は、各セットで6人とも1回ずつになるようにする（誰かの話から次に話す人を見つけられる）
* 選択肢の文（「話を聞く」「なんでもない」「仕事のこと」「村の人のこと」「ほかの話も聞く」「じゃあね」）は全員・両セットで同じ。「ほかの話も聞く」はまだ聞いていない方の話題へ進む（話題1のあとは話題2へ、話題2のあとは話題1へ）
* 長さもそろえる：どの話題も2ノード、1ノードは60字前後まで（会話窓の3行に収まる）
* 自由入力が出るのは1人3か所（`10`・`21`・`31`）。`nextId`を自分自身にして、何回でも続けて聞ける（4.3と同じ）
* **大前提**（1.3）：全員の話題2つずつ（1セット12個）は**すべて選択肢だけで聞ける**
* 同じ人に何回話しかけても同じ会話になる（前に聞いた話題を覚えておく仕組みは作らない）

| | セット1 | セット2 |
|---|---|---|
| 人数・位置 | 6人（NPC001〜006の位置） | 同じ |
| 衣装 | 商人・平民・薬師・貴族・鍛冶屋・料理人 | 同じ6種類を、どの位置でもセット1と違うように入れ替える |
| 話題 | 1人2つ（仕事のこと・村の人のこと）、各2ノード | 同じ |
| 話題2のつながり | 6人で1つの輪（全員が1回ずつ紹介される） | 同じ |
| 話題の調子 | 村の暮らしの軽い話（事件や謎はない） | 同じ |
| 自由入力の場面 | 1人3か所×6人＝18か所 | 同じ |

* 話題2では、紹介する人の**居場所**（「東の桟橋の手前」など）を必ず言う。ミニマップと合わせて、次に話す人を探せる

* セット1はクエスト版（1.7）と名前・性格は同じだが、会話もプロンプトも新しく書いたもの。クエスト版の手がかり（薬草・灯篭）は出てこない（ニコラの収穫祭の灯篭は飾る話だけで、なくなってはいない）

# 6. 実験ログ（承認・実装済み）

研究の分析に使うデータを、プレイ中に自動でファイルへ記録する（`ExperimentLogger`）。

## 6.1 方針

* **1プレイ（タイトルの「はじめる」〜終了）＝1セッション＝1ファイル**。1行に1つの出来事（イベント）を書く
* セッションの終わりに、集計結果を**1行だけ**`summary.csv`（全セッション共通）に追記する
* 途中でアプリが落ちても記録が残るよう、**1行書くたびにファイルへ書き出す**
* 文字コードはUTF-8（BOM付き）。Excelで開いても文字化けしない
* 参加者は`participantId`（例：P001）だけで識別し、氏名などは記録しない。**自由入力の文章はそのまま記録する**ので、実験の説明・同意書でその旨を伝えること
* プレイヤーの位置（移動の軌跡）は記録しない

## 6.2 保存場所

| 実行のしかた | 保存先 |
|---|---|
| ビルドしたアプリ（実験本番） | アプリ（.exe）と同じフォルダの`ExperimentLogs/` |
| Unityエディタ | `Assets/ExperimentLogs/`（`.gitignore`済み。GitHubには上げない） |

* エディタではUnityがCSVをテキストアセットとして取り込み、`.meta`を作る（ログの中身には影響しない）。`.meta`も`.gitignore`の対象

* ファイル名：`{参加者ID}_{条件}_S{話題セット番号}_{開始日時}.csv`（例：`P001_B_S2_20261012_143005.csv`）
* `summary.csv`も同じフォルダ
* 保存先のパスはセッション開始時にConsoleへ`[Log] Session log: …`と出る。タイトル画面の開発者用モーダルの下にも「ログ保存先：…」と表示する

## 6.3 記録するイベント

| event_type | いつ | 主な記録内容 |
|---|---|---|
| `session_start` | MainSceneの開始時 | `detail`にアプリのバージョン・Unityバージョン・AIモデル名・プラットフォーム（参加者ID・条件・話題セットは全行の列に入る） |
| `explore_start` | 説明画面を閉じて探索を始めた（5分の数え始め） | `detail`に制限時間（`duration=300`） |
| `dialogue_start` | NPCに話しかけた | NPC ID・開始ノードID（いつも0） |
| `npc_line` | NPCのセリフが表示された | NPC ID・ノードID・セリフ |
| `topic_heard` | 話題を聞いた（`topic:`のノードを表示した） | NPC ID・ノードID・`detail`に話題番号（`topic`）、それまでに聞いた話題の数（`topics_heard`、同じ話題を2回聞いても1つ）、話しかけたNPCの人数（`npcs_talked`） |
| `choice_select` | 選択肢を決定した | NPC ID・ノードID・選択肢の文・何番目か（「入力する」も含む） |
| `free_input_submit` | 自由入力を送信した | NPC ID・ノードID・入力した文章 |
| `free_input_cancel` | 自由入力を「やめる」で閉じた（3.7） | NPC ID・ノードID（書きかけの文章は記録しない）。集計（summary.csv）には入れない |
| `ai_response` | AIの返答が表示された | NPC ID・ノードID・返答・応答時間（ミリ秒）・エラーかどうか・プロンプトの識別子 |
| `dialogue_end` | 会話を閉じた | NPC ID・会話時間・この会話での選択回数・自由入力回数 |
| `time_up` | 5分たった | `detail`にそのときの状態（`state=InChoice`など） |
| `settings_open`／`settings_close` | 設定パネルの開閉 | 閉じたときの音量・感度。`duration`は開いていた**実時間**（パネル表示中は`play_time`が止まるため）。スライダーの細かい動きは記録しない |
| `respawn` | 「初期位置に戻る」を押した | 押す前の位置（`from_x`／`from_z`） |
| `session_end` | セッションの終わり | 終わり方（`time_up`／`back_to_title`／`app_quit`。それ以外でシーンが消えたときは`scene_unloaded`）・総プレイ時間。会話中・設定パネル表示中に終わった場合は、先にその`dialogue_end`／`settings_close`を書く |

* **AIのエラー**：返答が得られなかったら`is_error=1`にし、`detail`に理由（`error=…`）を書く（4.6）。プロンプトが見つからなかったときも`is_error=1`（`detail`は`prompt=none`）
* `npc_line`はノードを表示するたびに書く（AIの返答のあと同じノードに戻ったときも、もう一度書かれる）
* 会話時間（`dialogue_end`の`duration`）・会話ごとの選択回数と自由入力回数は、`ExperimentLogger`が自分で計算して書く
* 時間切れ（`time_up`）から終了画面（`session_end`）までの超過時間は、2つの`play_time`の差で分かる
* **プロンプトの識別子**：使った`PromptData`の場所（例：`S1/NPC005`）と、本文のハッシュ値（先頭8文字）。実験期間中にプロンプトが変わっていないかを後から確認できる（1.5）

## 6.4 時間

* `timestamp`：PCの時計の日時（例：`2026-10-12T14:30:05.123`）
* `play_time`：MainSceneを開始してからの秒数（小数3桁）。**設定パネルで時間を止めている間は進まない**（`Time.timeSinceLevelLoad`）。説明画面を出している間は進む（5分の数え始めは`explore_start`の`play_time`）

会話時間・探索時間などは`play_time`の差で計算する。

## 6.5 実装の構成

`ExperimentLogger`（MainSceneの`GameManager`に付けてある）がファイルの作成・書き込み・集計を担当し、他のスクリプトからは`ExperimentLogger.Log(...)`の1行で呼ぶ。AIのモデル名は`ChatGPTClient.ModelName`から読む。

| クラス | 場所 | イベント |
|---|---|---|
| `DialogueManager` | `StartNode`／`ShowNode`／`ExecuteNodeAction`／選択肢の決定／`SubmitTypedText`／`OnClickCancelInput`／`ShowAIResponse`／`CloseDialogue`／`HandleTimeUp`／`OpenSettings`／`CloseSettings`／`RespawnPlayer` | dialogue_start／npc_line／topic_heard／choice_select／free_input_submit／free_input_cancel／ai_response／dialogue_end／time_up／settings_open／settings_close／respawn |
| `ExplorationTimer` | `Begin` | explore_start |
| `SettingsPanelUI` | 「タイトルへ戻る」 | session_end（back_to_title） |
| `DialogueManager` | `EndGame`（終了画面） | session_end（time_up） |
| `ExperimentLogger` | 開始時／アプリ終了時（エディタのPlay停止も含む） | session_start／session_end（app_quit） |

## 6.6 イベントログの形式

```csv
session_id,participant_id,condition,set,timestamp,play_time,event_type,npc_id,node_id,text,player_input,choice_index,clue_id,duration,is_error,detail
```

| 列 | 内容 |
|---|---|
| `session_id` | セッションのID（開始日時＋参加者ID） |
| `participant_id`／`condition`／`set` | 全行に入れる（複数ファイルを結合して分析しやすいように）。`set`は話題セット番号 |
| `timestamp`／`play_time` | 6.4 |
| `event_type` | 6.3 |
| `npc_id`／`node_id` | 対象のNPCとノード |
| `text` | NPCのセリフ・選んだ選択肢の文・AIの返答 |
| `player_input` | 自由入力の文章 |
| `choice_index` | 選んだ選択肢の順番（0始まり） |
| `clue_id` | 使っていない（クエスト版の手がかりID。列の並びを変えないよう空欄で残している） |
| `duration` | 会話時間・設定パネルを開いていた時間など（秒） |
| `is_error` | AIのエラーなら1 |
| `detail` | その他（`key=value`を`;`区切り。例：`prompt=S1/NPC005;hash=3fa2c91b;latency_ms=1840`） |

使わない列は空欄。文章にカンマ・改行・`"`が含まれても崩れないよう、`"`で囲む。

## 6.7 集計ファイル（summary.csv）

1セッション1行。

```csv
session_id,participant_id,condition,set,start_time,end_reason,total_play_time,explore_start_time,time_up_time,dialogue_count,choice_count,free_input_count,ai_error_count,ai_wait_total,npcs_talked,topics_heard,settings_open_count,respawn_count,talk_NPC001,talk_NPC002,talk_NPC003,talk_NPC004,talk_NPC005,talk_NPC006
```

* `*_time`：そのイベントが起きた`play_time`（起きなければ空欄）
* `ai_wait_total`：AIの返答待ちの合計秒数（`ai_response`の`latency_ms`の合計）。条件Bでは5分のうちこの分だけ歩く・話す時間が減るので、分析で考慮できるように入れている
* `npcs_talked`：話しかけた人数（0〜6）、`topics_heard`：聞いた話題の数（0〜12）
* `talk_NPC00x`：そのNPCとの会話の回数と合計時間（例：`3/42.5`＝3回・42.5秒）
* イベントログから計算し直せる内容だが、条件A・Bの比較をすぐできるように用意する
* 既にある`summary.csv`の1行目が今の列と違う（クエスト版のものなど）ときは、`summary_old_{日時}.csv`に名前を変えてから新しく作る（列がずれた行が混ざらないように）

# 7. 環境・アセット

## 7.1 Unityとパッケージ

* Unity 6000.4.2f1
* Universal Render Pipeline 17.4.0
* Input System 1.19.0（会話まわりは`Keyboard.current`を直接見ている）
* Cinemachine 3.1.7
* TextMeshPro（日本語フォント：`Assets/Fonts/NotoSansJP-Regular SDF`）
* Starter Assets Third Person Controller（購入アセット）

## 7.2 シーン

| シーン | ビルド番号 | 内容 |
|---|---|---|
| `Assets/TitleScene.unity` | 0 | タイトル画面（3.1） |
| `Assets/MainScene.unity` | 1 | 村。`GameManager`オブジェクトに`GameManager`・`DialogueManager`・`ChatGPTClient`・`ExperimentSettings`・`ExplorationTimer`・`AudioVolumeSettings`・`LookSensitivitySettings`・`ExperimentLogger`が付いている |

## 7.3 プレイヤーとカメラ

* 見た目は購入アセットの`Axe_Warrior`を`PlayerArmature`の子として使う。モデルの横位置は回転の中心に合わせてある（`localPosition.x = 0`。ずれていると片足を軸に回っているように見える）
* カメラは`PlayerFollowCamera`（`Cinemachine3rdPersonFollow`）。`CameraSide = 0.5`でキャラクターを画面の中央に映す（0.5〜1にすると右肩越しの視点になる）
* `ThirdPersonController.cs`（購入アセット）は、このプロジェクト用に手を入れてある（足音まわり・`StopMotion()`）。7.7を参照

## 7.4 音

AudioMixerは使わず、音量を1か所（`AudioVolumeSettings`）で持ち、各`AudioSource`に付けた`VolumeChannel`（BGM／SE）が「元の音量×設定音量」を反映する。

| 種類 | 音源 | 備考 |
|---|---|---|
| BGM | シーンのルートの`BGM`（`Assets/Audio/BGM.wav`、約82秒） | ループ再生・起動時に自動再生・2D。読み込みはStreaming・Vorbis品質70% |
| SE | `Player/PlayerArmature/Audio/`の`Footstep_Concrete`・`Footstep_Land` | 足音・着地音 |

* 初期値はBGM・SEとも80%。保存しない（1.4）
* 新しい音を足すときは、その`AudioSource`に`VolumeChannel`を付ける

## 7.5 空とライティング

* 空はAsset Storeの無料素材「Simple Sky - Cartoon assets」。シーンのルートの`Sky`の中に、空のドーム（`SkyDome`、村の中心(11, 0, 128)・スケール1.3・半径約430m）とローポリの雲12個（`Clouds`）を置いている。どれも影を落とさない
* ドームと雲には、素材のマテリアルをコピーした`Assets/Material/SimpleSky_Day.mat`（UVオフセット**−0.05**＝明るい昼の青空）を使う。オフセットで時間帯が変わる（0.1付近で夕方寄り、0.2で夕方、0.3以降で夜）。ドームの月（`Moon`）と星（`Stars`）は非表示
* ドームはカメラの描画距離（500m）の内側に収めてある。ドームを大きくしたりカメラのFar Clipを小さくしたりすると空が消える
* スカイボックスは使わない。環境光は3色指定（空 RGB(140,184,242)・地平線 RGB(199,209,219)・地面 RGB(107,115,92)）。太陽（`Directional Light`）は色温度6500K（昼の白い光）
* 焼き込みライティングは使わない（`Assets/Settings/MainSceneLighting.lighting`：Baked GI・Realtime GIともオフ）。環境光のデータは`Assets/MainSceneLight/LightingData.asset`

## 7.6 水に入れないようにする壁

* 水面（`Background/Landscape/Water`、y=−0.9）まで岸の地面がなだらかに続いていて、そのままでは浅瀬に入れてしまう。そこでシーンのルートの`WaterBlockers`に、岸に沿って見えない当たり判定の箱（`Blocker`、697個・高さ6m）を並べている
* 0.5m四方ごとに「水面以外の当たり判定の一番高い所が水面より低いか」を調べ、陸と接している水のマスにだけ置いた。桟橋・岩・ボートは陸として扱うので、桟橋の上は先端まで歩ける
* 箱は`Water`レイヤー。カメラの衝突判定（`Default`のみ）に含まれないので、カメラが押し戻されることはない
* 岸の地形・桟橋・水面の高さを変えたら、Unityのメニュー **Tools → 研究用 → 水の壁を作り直す** で作り直す（`Assets/Editor/SceneBuildTools.cs`）

## 7.7 GitHubに含まれないもの・別のPCで開くとき

# 9. 開発の進め方

Claude Codeが本仕様書を参照し、Unity MCP経由で開発する。

## 9.1 設計から実装まで

1. 新しい機能・変更は、まずREADMEに設計を書き、見出しに「**案・レビュー待ち**」と付ける
2. ユーザーが確認・承認する
3. 承認後に実装する（1ファイルずつ）。終わったら見出しを「**承認・実装済み**」にし、READMEの内容を実装に合わせる

## 9.2 基本ルール

* 既存の実装を確認してから変更する。推測だけでUnityの状態を判断せず、Unity MCPで確認する
* 不要な既存機能を削除しない。既存のクラスの役割を尊重する
* 1回の変更で大量のファイルを変更しない
* 変更したらUnityでコンパイルし、Consoleのエラーを確認する。エラーがあれば直してから次へ進む
* 研究仕様（1.6）は勝手に変えない
