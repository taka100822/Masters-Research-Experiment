# 1. 研究と実験

## 1.1 目的

修士研究「生成AIを用いた自由入力機能の導入が、プレイヤーの対話行動およびゲーム体験に与える影響」のための研究用RPGプロトタイプ。プレイヤーは小さな村を探索し、NPCとの会話からクエスト達成に必要な手がかりを集める。NPCとの**対話方式の違い**がプレイヤーの対話行動とゲーム体験に与える影響を比較する。

## 1.2 実験条件

| 条件 | 対話方式 |
|---|---|
| **A：選択肢のみ** | ゲーム側が用意した選択肢からプレイヤーが発言を選ぶ |
| **B：選択肢＋自由入力** | Aと同じ選択肢に加え、決められた場面で「入力する」を選ぶと文章を入力でき、生成AIがNPCとして返答する |

* 条件はクエストやNPCに結び付けず、「参加者が今どちらの条件で遊んでいるか」という**全体設定**として持つ。同じNPC・同じクエストでも、条件Aでは選択肢だけ、条件Bでは同じ場面に「入力する」が加わる
* 設定は実験者がタイトル画面の開発者用モーダルで行う（3.1）。実装上は「`allowInput=1`のノード、かつ条件B」のときだけ「入力する」が出る（4.2）

## 1.3 クエストとカウンターバランス

参加者は条件A・Bの両方をプレイする。同じクエストを2回遊ぶと答えを覚えてしまうので、内容は違うが構成・難易度をそろえたクエストを2つ用意する（5章）。

* クエスト1：「消えた薬草」
* クエスト2：「祭りの道具探し」

クエストと条件を固定のペアにすると、体験の違いが対話方式によるのかクエスト内容によるのか区別できない。そのためクエストと条件は独立させ、参加者を次の4グループに均等に振り分ける。

1. 条件A×クエスト1 → 条件B×クエスト2
2. 条件A×クエスト2 → 条件B×クエスト1
3. 条件B×クエスト1 → 条件A×クエスト2
4. 条件B×クエスト2 → 条件A×クエスト1

**大前提**：クエスト達成に必要な手がかりは**すべて選択肢だけで入手できる**。自由入力は会話を掘り下げるための追加の手段で、手がかりの入手には必要ない（条件Aでも同じように達成できる）。

## 1.4 条件以外の差を小さくする

ゲームとしての面白さより、実験条件の統制を優先する。マップ・NPCの配置と外見・会話・クエストの構成・UI・操作・BGM/SE・グラフィックは、両条件・両クエストで同じにする。主な違いは対話方式だけにする。

* 2つのクエストの対応は5.6、会話の型の統一は5.3
* ミニマップ・NPCの名前表示・依頼人の色分けは、両クエスト・両条件で同じように出る（探索の手がかりにはなるが、条件差にはならない）
* 音量・視点感度は**保存せず、起動するたびに初期値に戻す**（前の参加者の設定が次の参加者に引き継がれないように）

## 1.5 研究データの再現性

Unityバージョン・AIモデル・API仕様・NPCプロンプト・会話データ・クエストデータ・ゲームバージョン・実験日時・実験条件を固定し、記録する。特に条件Bでは、**実験期間中にプロンプトやモデルを変更しない**。ログには使ったプロンプトの識別子とハッシュ値を残して、後から確認できるようにする（6章）。

## 1.6 研究仕様の変更ルール

次のものは勝手に変更しない：実験条件、NPCの知識（手がかり）、クエスト達成条件、ログ項目、AIモデル、AIプロンプト、会話方式。変更が必要なときは、まず変更内容と研究上の影響を説明する。

# 2. ゲームの概要

## 2.1 規模

* ジャンル：小規模な探索型RPG（戦闘・成長システムなし）
* プレイ時間：1プレイ10〜20分程度
* マップ：村1つ（`Assets/MainScene.unity`、購入アセットのVillageを使用）
* NPC：6人（5.2）
* クエスト：2つ。1回のプレイでは設定で選んだ1つだけを遊ぶ
* セーブ：なし（1回のプレイを最初から最後まで行う）

## 2.2 ゲームの流れ

```text
タイトル画面（実験者が開発者用モーダルで参加者ID・条件・クエストを設定）
 ↓ はじめる
村に降り立つ
 ↓
依頼人に話しかけて依頼を引き受ける（右上にチェックリストが出る）
 ↓
村を探索し、NPCから手がかりを4つ集める
 ↓
依頼人に報告 → クエスト達成 → 終了画面（操作不可）
```

プレイ中はいつでも`Q`で設定パネルを開ける（探索中のみ）。設定パネルから「タイトルへ戻る」と、進み具合はリセットされる。

## 2.3 操作

| キー | 操作 |
|---|---|
| WASD | 移動 |
| マウス | カメラ操作 |
| Space | ジャンプ |
| Enter | 話しかける／会話を進める／選択肢を決定する |
| ↑ ↓ | 選択肢を選ぶ |
| Q | 設定パネルを開く・閉じる（探索中のみ） |
| マウスクリック | 自由入力の「送信」（空欄では押せない）・「やめる」（選択肢に戻る）ボタン・設定パネル・タイトル画面の操作 |

移動・カメラは Starter Assets Third Person Controller（購入アセット）の標準入力。会話まわりの入力は`DialogueManager`が`Keyboard.current`を直接見ている。

# 3. 画面とUI

## 3.1 タイトル画面

ゲームを起動すると最初に出る画面（`Assets/TitleScene.unity`、ビルド設定の0番）。

見た目・配置の詳細は3.8。

```text
┌──────────────────────────────────────┐
│                                      │
│        研 究 用 ゲ ー ム              │  ← 大きなタイトル文字（TitleText）
│                                      │
│           [  はじめる  ]              │
│                                      │
│ P000・A・Q1              [開発者用]    │  ← 現在の実験設定（実験者の確認用・目立たない表示）
└──────────────────────────────────────┘
```

* **はじめる**：MainSceneへ移る
* **開発者用**：開発者用モーダルを開く
* 背景は村の全景をぼかした画像（`Assets/Texture/title_background_blur.png`。元画像`title_background.png`にガウスぼかし半径12px）に黒25%の暗幕を重ねたもの
* 設定表示は`参加者ID・条件・Q番号`の短い形で、「条件」という言葉は出さない（参加者が自分の条件を意識しにくくするため）
* タイトル画面ではカーソルを表示する

**開発者用モーダル**

```text
┌────────────────────────────────┐
│ 開発者用設定                      │
│ 参加者ID   [ P000            ]   │
│ 対話条件   [ A：選択肢のみ    ▼]  │  ← A：選択肢のみ／B：選択肢＋自由入力
│ クエスト   [ 1：消えた薬草    ▼]  │  ← 1：消えた薬草／2：祭りの道具探し
│ ログ保存先：…                     │
│          [ キャンセル ] [ 決定 ]   │
└────────────────────────────────┘
```

* 「決定」で値を反映し、タイトルの設定表示も更新する。参加者IDが空なら閉じられない（「参加者IDを入力してください」）
* 「キャンセル」で値を変えずに閉じる。次に開いたときは`ExperimentConfig`の値が入り直す
* 開いている間はタイトル文字と「はじめる」を隠す（窓の後ろからはみ出して見えないように）

**設定の受け渡し**

* タイトルで設定した値はstaticな`ExperimentConfig`に置き、MainSceneの`ExperimentSettings`が起動時（`Awake`）に読む。読んだ値はConsoleに`[Experiment] participant=… condition=… quest=…`と出る
* エディタでMainSceneを直接Playしたときは、`ExperimentSettings`のInspectorの値を使う
* ファイルには保存しない。アプリを起動し直すと初期値（P000／条件A／クエスト1）に戻る

## 3.2 プレイ画面のUI構成

```text
Canvas（Screen Space Overlay）
├── TalkHint                話しかけ案内の札（TalkHintText）
├── ChoicePanel             選択肢（ChoiceRow1〜3 > Choice1〜3Text）

├── Minimap                 右上のミニマップ（3.4）
├── QuestPanel              ミニマップの下のチェックリスト（3.5）
├── QuestCompletePanel      終了画面（3.5）
└── SettingsPanel           設定パネル（3.6）
```

見た目・配置の詳細は3.7。

```text
                              ┌────────────┐
                              │▶ 選択肢A     │
                              │  選択肢B     │
                              │  入力する    │ ← 条件Bかつ allowInput=1 のノードのみ
                              └────────────┘
 ╔══════════╗
┌╨薬師ジョン╨─────────────────────────┐ ← 名前は吊り看板（displayName）
│ NPCのセリフ／AIの返答                 │
│              [Enter] 次へ  ▼        │ ← 操作案内

```

* 会話中はプレイヤーの移動・カメラ操作を止める
* 自由入力中も会話ウィンドウ（直前のセリフ）は表示したまま、その上に入力欄と「やめる」「送信」ボタンを出す
* 近くのNPCがいると`TalkHint`（画面下中央、`[Enter] ○○と話す`）とNPC頭上の吹き出し（3.3）の両方が出る

## 3.3 NPCの頭上UI

各NPCの`HeadUI/Canvas`（ワールド空間。`Billboard`で常にカメラの方を向く）に次の2つがある。下から 頭 → 名前 → 吹き出し の順に並ぶ。

* **名前**（`NameLabel`）：常に表示。`NPCDialogue.displayName`を起動時に`NPCInteraction`が入れる。白文字＋黒縁（`NotoSansJP-Regular SDF - NameOutline.mat`）。建物の陰では隠れる
* **吹き出し**（`Image`）：プレイヤーが近づいて会話できる範囲に入ったときだけ表示
* **依頼人の色分け**：プレイ中のクエストの依頼人（`QuestData.clientNpcId`。Q1はNPC003、Q2はNPC004）だけ、名前と吹き出しを金色（`NPCInteraction.clientColor`、RGB(255, 210, 50)）にする。ミニマップの依頼人アイコンも同じ値を参照する

## 3.4 ミニマップ

画面右上（170×170px）に、プレイヤーを中心にした地図を常に表示する。

* 地図はエディタで村の真上から1回だけ撮影した静止画（`Assets/Texture/minimap_village.png`、中心(11, 128)・一辺128m）。実行中は表示範囲（`RawImage.uvRect`）を動かしてスクロールさせる
* プレイヤーの周り一辺30mを表示。**北が上で固定**し、プレイヤーの三角アイコンが向きを指す

| 対象 | 形 | 色 |
|---|---|---|
| プレイヤー | 三角（`minimap_arrow.png`） | 水色 |
| NPC | 丸（Unity標準の`Knob`） | 白 |
| 今のクエストの依頼人 | 少し大きい丸 | 金色（`clientColor`） |

* 表示範囲の外のNPCは隠す。**依頼人だけは範囲外でも縁に止めて表示**し、方向が分かるようにする
* NPCの配置や建物を変えたら、Unityのメニュー **Tools → 研究用 → ミニマップの地図を撮り直す** で撮り直す（撮影範囲は`MinimapUI`の`mapWorldCenter`／`mapWorldSize`から自動で読む。NPCとプレイヤーは写らない）

## 3.5 クエストのチェックリストと終了画面

**チェックリスト**（`QuestPanel`）：依頼を引き受けると、ミニマップの下に表示される。

```text
消えた薬草
■ 場所：村の入り口
□ 時間
□ 人物
■ 特徴：赤い布に包まれた束
```

* 未入手の手がかりはカテゴリ名だけ（内容は伏せる）。入手すると内容を表示する
* 手がかりを集める順番は自由

**終了画面**（`QuestCompletePanel`）：依頼人への報告で達成し、その会話を閉じると全画面に「クエスト達成！ お疲れさまでした。実験者の指示があるまでお待ちください。」を表示する。以後は移動・会話とも操作不可（`GameState.Ended`）。BGMは鳴り続ける。

## 3.6 設定パネル

探索中に`Q`で開き、`Q`で閉じる（`Esc`は使わない）。

```text
┌────────────────────────────┐
│ 設定                        │
│ BGM   ━━━━━━━●━━━  80%      │
│ SE    ━━━━━━━●━━━  80%      │
│ 感度  ━━━━●━━━━━━  1.0      │
│      [ タイトルへ戻る ]      │
│      [ 初期位置に戻る ]      │
│        Q：閉じる            │
└────────────────────────────┘
```

* **開けるのは探索中だけ**。会話中・選択肢中・自由入力中・終了画面では開かない（自由入力で「q」を打っても開かないように）
* 開いている間は**ゲーム内の時間を止める**（`Time.timeScale = 0`）。音は止めない（スライダーを動かしながら音量を確かめられるように）。カーソルを表示し、プレイヤー操作を止める
* **BGM・SE**：0〜100%、初期値80%（7.4）
* **感度**：視点を回す速さの倍率。0.2〜3.0、初期値1.0。`LookSensitivitySettings`が`PlayerInput`のLookアクションに、元のプロセッサ（マウス×0.05など）の後ろへ`ScaleVector2(x=感度,y=感度)`を実行中だけ追加する（購入アセットの入力設定は変更しない）
* **タイトルへ戻る**：TitleSceneへ戻る（クエストの進み具合はリセット）
* **初期位置に戻る**：ゲーム開始時の位置・向きへ瞬間移動し、パネルを閉じる。建物の隙間にはまったときなどの救済用。クエストの進み具合はそのまま。カメラが村の上空を横切らないよう、Cinemachineに瞬間移動を伝えている（`OnTargetObjectWarped`）

## 3.7 会話UIのデザイン（承認・実装済み）

10.1 Phase 9「UI調整」の一部（2026-10-05 実装）。MainSceneの会話まわりのUIを、村の世界観に合わせつつ「誰が話しているか／何を言っているか／何を選べるか／何キーで決定・送り・やめるか」が一目で分かるようにした。

### 改善前の問題（2026-10-05 Unity上で確認）

| # | 問題 |
|---|---|
| 1 | 選択肢パネルが右上のチェックリストに重なる（右下から上へ伸びるため） |
| 2 | 選ばれている選択肢が文字色（黄色）だけで分かりにくい。カーソルや下地がない |
| 3 | 名前と本文が同じ黒い窓の中で、同じ白・ほぼ同じ大きさ。誰の発言かが目立たない |
| 4 | 「次へ」の▼が窓の外（下）にあり、半透明で見落としやすい。操作キーの案内がどこにもない（会話中に「Enterで進む」「↑↓で選ぶ」が分からない） |
| 5 | 自由入力欄が画面中央に半透明で浮き、背景の村と重なって読みにくい。送信ボタンも白っぽく目立たない |
| 6 | 自由入力を**やめる手段がない**。「入力する」を選ぶと、何か送信するまで会話から抜けられない。空欄でも送信できる |
| 7 | 「Enterで話す」が画面右下の白文字だけで、明るい地面の上だと読めない。誰に話しかけるのかも分からない |
| 8 | Canvasが`Constant Pixel Size`。ビルドは全画面（1920×1080など）で動くので、UIが小さくなる（Gameビュー1069×601で作られている） |

### デザインの方針

* **村の建物から取る**：村は木組み（ハーフティンバー）の家・橙の屋根・白い漆喰壁。会話窓は**濃い樫材の板**、縁は**真鍮の細線**、文字は**漆喰の白**にする。いまの黒×銀の窓より村になじみ、明るい背景の上でも読める
* **印象に残すのは1か所だけ**：NPCの名前を、窓の左上の縁にかかる**吊り看板**（店の看板の形）にする。それ以外は静かにそろえる
* **条件差を作らない（1.4）**：「入力する」も他の選択肢と**同じ見た目**にする（アイコン・色分けをしない）。条件Bで増えるのは選択肢1行と、入力中の窓だけ
* 動きは「次へ」の▼が上下にゆっくり揺れるだけ（会話送りできることを知らせる）

**色**

| 名前 | 値 | 使う所 |
|---|---|---|
| 樫（窓の地） | `#2A1E16`・不透明度94% | 会話窓・選択肢・入力窓・話しかけ案内 |
| 梁（看板の地） | `#5A3A22` | 名前の吊り看板 |
| 真鍮（線・カーソル） | `#E0B354` | 窓の縁線・選択中のカーソル▶と下地（25%）・▼・操作案内のキー（`[Enter]`など） |
| 漆喰（本文） | `#F6EEDC` | 名前・本文・選択中の選択肢 |
| 煤（控えめな文字） | `#B9A88E` | 選ばれていない選択肢・操作案内・入力欄のプレースホルダー |

* 依頼人の金色（`clientColor`）・チェックリストの見出しの金色とは近い系統の色なので、画面全体の色がまとまる
* **文字**はいまの`NotoSansJP-Regular SDF`のまま（日本語フォントを増やさない）。大きさと太さで差をつける：名前26（TMPの太字）、本文24（行間+10%）、選択肢22、操作案内16（基準解像度1280×720のときの値）

**窓の素材**：白い角丸の板（`ui_panel_fill.png`）と、角丸の縁線（`ui_panel_frame.png`）を1枚ずつ作り（`Assets/Texture/`、9スライス）、`Image`の色で塗り分ける。購入アセットやいまの黒×銀の画像（`panel_rect_black-silver_03_128.png`）は変更しない。

# 4. 会話システム

## 4.1 状態

`GameState`（`Assets/Script/GameState.cs`）。状態を持ち、遷移させているのは`DialogueManager`（`currentState`）。

| 状態 | 内容 |
|---|---|
| `FreeMove` | 探索中。移動・カメラ操作ができる。近くにNPCがいればEnterで話しかけられる。Qで設定パネル |
| `InDialogue` | 会話中（選択肢なし）。Enterで次へ |
| `InChoice` | 選択肢を選んでいる。↑↓で移動、Enterで決定 |
| `InTyping` | 自由入力中。送信はボタンのみ（IME変換中のEnterで誤送信しないよう、Enterでは送らない）。「やめる」ボタンで同じノードの選択肢（`InChoice`）に戻る |
| `Ended` | クエスト達成後の終了画面。操作不可 |
| `InSettings` | 設定パネル表示中。時間停止 |

プレイヤーを止めるときは必ず`DialogueManager.StopPlayer()`を通す。`ThirdPersonController`を無効にするだけでは、走りながら話しかけたときに走りモーションと足音（アニメーションイベント）が続いてしまうため、速度を0にする`StopMotion()`も呼ぶ（7.3）。

## 4.2 会話の進み方

会話は会話データ（CSV）の**ノード**を順にたどる（4.4）。

* 1ノードの選択肢は最大3つ：`choiceA`、`choiceB`（それぞれ空でなければ表示）、「入力する」（`allowInput=1`かつ条件Bのときだけ自動で追加）
* 選択肢が1つも無いノードでは「次へ」の案内だけを出し、Enterで`nextId`へ進む。`nextId=-1`なら会話を終える
* 「何も聞かない」のような選択肢は、`choiceA`／`choiceB`の文として書き、遷移先に終了用のノードを置く

## 4.3 自由入力とAIの返答

```text
「入力する」を選ぶ → 入力欄を表示（カーソル表示・移動停止）
 ↓ 送信ボタン
AIへ送信（返答を待つ間もプレイヤーは動けない）
 ↓
AIの返答をNPCのセリフとして表示
 ↓ Enter
「入力する」を選んだノードの nextId へ進む（-1なら会話終了）
```

* AIの返答のあとに進む先は、自由入力を始めた**元のノードの`nextId`**
* クエストの会話では、自由入力を出すノードの`nextId`を**自分自身のID**にしている。返答のあとEnterで同じノード（同じ選択肢＋「入力する」）に戻るので、何回でも続けて質問でき、「ありがとう」などの選択肢で会話を終えられる
* AIは会話の履歴を持たない（毎回、システムプロンプト＋今回の入力だけを送る）

## 4.4 会話データ（CSV）

`Assets/Resources/dialogue/`に、NPC1人につき1つのCSVを置く（`DialogueDatabase`が、会話を始めるときに読み込む）。

```text
id, text, nextId, choiceA, choiceA_next, choiceB, choiceB_next, allowInput, action
```

| 列 | 内容 |
|---|---|
| `id` | ノードID |
| `text` | NPCのセリフ（**半角カンマは使えない**。読点「、」を使う） |
| `nextId` | 選択肢が無いときの次のノード（`-1`で終了） |
| `choiceA`／`choiceA_next`、`choiceB`／`choiceB_next` | 選択肢の文と遷移先 |
| `allowInput` | `1`なら条件Bで「入力する」を出す（列が無いCSVは0扱い） |
| `action` | ノードを表示した瞬間に実行する：`startQuest`（依頼を受ける）／`clue:<手がかりID>`（手がかりを得る）／`complete`（達成）。空なら何もしない |

**読み込む場所**：`Dialogue/Q{クエスト番号}/{csvFileName}` → `Dialogue/Common/{csvFileName}` の順に探す。クエストに関係するNPCは`Q1/`・`Q2/`、関係ないときの世間話は`Common/`に置く。

**会話を始めるノード**：クエストの状態ごとに決まっていて、そのIDのノードが無ければ次の候補へ進む。

| クエストの状態 | 開始ノード | 無い場合 | 依頼人 | 手がかりを持つNPC |
|---|---|---|---|---|
| 受注前 | `0` | — | 依頼の説明 | 世間話（手がかりは出さない） |
| 進行中・手がかり不足 | `100` | `0` | 「まだ足りない」 | 手がかりの会話 |
| 進行中・4つ揃った | `200` | `100`→`0` | 報告 → `complete` | （書かない＝`100`のまま） |
| 達成済み | `300` | `0` | （終了画面になるので通常は来ない） | （書かない） |

`Common/`の世間話は`0`だけ書けばよい。

## 4.5 生成AI

* **API**：OpenAI Chat Completions API（`https://api.openai.com/v1/chat/completions`）に`UnityWebRequest`で送る（`ChatGPTClient`）。`ChatGPTClient`は通信だけを担当し、UIやプレイヤー操作には触れない
* **APIキー**：`Assets/Resources/openai_key.txt`から読む（`.gitignore`済み。GitHubには上げない）
* **モデル**：`ChatGPTClient.cs`の定数`model = "gpt-5.6-luna"`（2026-10-05に動作確認済み）。実験期間中は変えない（1.5）
* **プロンプトの読み込み**：`PromptData/Q{クエスト番号}/{npcId}` → `PromptData/Common/{npcId}` → `NPCDialogue.promptData` の順に探す（`DialogueManager.LoadPromptData()`）。どれも無ければ送信せず、NPCのセリフとして「……（今は話せないようだ）」を表示してConsoleにエラーを出す
* **プロンプトの形式**：`PromptData`（ScriptableObject）の`systemPrompt`という1つの文字列。名前・性格・知っている情報などは、下のテンプレートに沿って文章の中に書く
* **エラー**：通信の失敗・時間切れ（20秒）・返答の解析失敗・APIキーが無い、のどれでもゲームは止まらず、参加者向けの一文を表示する（4.6）

**AIに守らせること**（プロンプトの文面で守らせる。コード側での検査はしていない）

* NPCの設定から外れない。存在しない人物・場所・アイテムを作らない
* クエストの答えや手がかりの内容を変えない。新しい手がかりを作らない
* ゲーム外の情報を出さない。自分がAIであることに触れない
* 80文字以内の日本語で答える

**プロンプトのテンプレート**

```text
あなたは村に住む{{役職}}の{{名前}}です。

【性格】
{{一言で表せる人物像}}

【背景】
{{今何をしていて、なぜその情報を知っているのか}}

【知っている情報】
{{そのNPCが持つ手がかりの内容そのもの（依頼人なら依頼の内容と状況）}}

【知らない情報・話してはいけないこと】
- 「知っている情報」以外のこと（他の村人が知っている手がかりや、{{クエストの答え}}）は知らない。聞かれたら「分からない」と答える
- ゲームに存在しない場所・人物・アイテムを話に出さない
- 「知っている情報」の内容を変えたり、新しい手がかりを作り出したりしない
- 自分がAIであることには触れない

【会話のルール】
- 80文字以内の自然な日本語で答える
- {{名前}}らしい口調を保つ
- 深く聞かれた場合も、「知っている情報」と矛盾しない範囲で少し詳しく答えてよい（様子や気持ちを描写する程度）
- 手がかりと関係ない質問には、村の住人として短い世間話で答える
```

`{{クエストの答え}}`はクエスト1が「薬草がどうなったかの答え」、クエスト2が「灯篭がどこにあるかの答え」。【知らない情報】と【会話のルール】は全員同じ文面にする。

## 4.6 AIの返答が得られなかったとき（承認・実装済み）

参加者が「壊れた」と感じたり、操作できなくなったりしないようにする。

**待っている間**
* 送信したら、会話ウィンドウのセリフを「……」にして、返答を待っていることが分かるようにする（今は直前のセリフが出たまま止まって見える）

**時間切れ**
* 今は問い合わせに制限時間が無く、通信が固まると参加者がずっと待たされて操作できなくなる。**20秒**で打ち切り、エラーとして扱う（`UnityWebRequest.timeout`）

**エラーのときの表示**
* 「エラー」の代わりに、世界観を壊さない一文をNPCのセリフ欄に出す：
  `（うまく伝わらなかったようだ。もう一度話しかけてみよう）`
  （かっこ書きのナレーションにして、NPC本人のセリフに見えないようにする。全NPC共通）
* エラーかどうかは、`ChatGPTClient.SendChatMessage`が返す`ChatResult`（`Success`／`Text`／`Error`）で判定する。「エラー」という文字列はもう返さない

**もう一度試す**
* エラーのあとEnterを押すと、これまでどおり同じノードの選択肢（「入力する」を含む）に戻る（5.3の`nextId`＝自分自身の仕組み）
* そこで「入力する」を選ぶと、**失敗した文章が入力欄に残っている**ので、そのまま送信し直せる（成功したら入力欄は空に戻す）

**ログ**
* `ai_response`の`text`には参加者に表示した一文を、`detail`に失敗の理由を書く（`error=timeout`／`network`／`http_<コード>`／`parse`／`no_key`）。`is_error=1`は今までどおり

| 要素 | 内容 |
|---|---|
| `QuestData`（`Resources/Quest/Q1`・`Q2`） | クエスト番号・タイトル・依頼人の`npcId`（`clientNpcId`）・手がかり4つ（`clueId`／カテゴリ名／内容）。`clueId`は両クエスト共通で`place`／`time`／`person`／`feature` |
| `QuestManager` | 状態（受注前／進行中／達成）と取得済みの手がかりを管理。`StartQuest()`／`AddClue(id)`／`Complete()`は会話データの`action`から呼ばれる。`Complete()`は4つ揃っているときだけ成功する |
| `QuestPanelUI` | チェックリストの表示（3.5） |

* 手がかりは必ず**選択肢の先のノード**で渡す（条件Aでも同じ手順で4つ揃う）。AIの返答から手がかりが付与されることはない
* 依頼人に手がかり不足のまま報告しても「まだ足りない」と言われるだけで、達成にはならない

## 5.3 会話の型（全NPC・両クエスト共通）

| 場面 | 型 |
|---|---|
| 依頼人・受注前（`0`〜） | 事情説明 → 「引き受ける／今は無理」。**自由入力あり**（依頼の内容を詳しく聞ける） |
| 依頼人・手がかり不足（`100`） | 「まだ足りない」と言うだけ |
| 依頼人・報告（`200`〜） | 集めた手がかりを確認 → 謎が解ける → `complete` |
| 手がかりを持つNPC・受注前（`0`） | 世間話1行だけ。手がかりは出さない |
| 手がかりを持つNPC・受注後（`100`〜） | 「何か知らない？／なんでもない」→ 手がかりを話す（`clue:`）→「ありがとう」。**手がかりを話したノードで自由入力あり** |
| 関係ないNPC（`Common/`） | 世間話1行だけ |

* 同じ人の世間話（受注前の`0`と`Common/`）は、両クエストで同じ文にしている
* 自由入力が出るのは1クエストにつき4か所（依頼の説明＋手がかりを聞いた後×3人）

以下の表の書き方：`→`は遷移先、`終`は会話終了（`-1`）、「入力」の○は`allowInput=1`（括弧内は`nextId`）。

# 6. 実験ログ（承認・実装済み）

研究の分析に使うデータを、プレイ中に自動でファイルへ記録する（`ExperimentLogger`）。

## 6.1 方針

* **1プレイ（タイトルの「はじめる」〜終了）＝1セッション＝1ファイル**。1行に1つの出来事（イベント）を書く
* セッションの終わりに、集計結果を**1行だけ**`summary.csv`（全セッション共通）に追記する
* 途中でアプリが落ちても記録が残るよう、**1行書くたびにファイルへ書き出す**
* 文字コードはUTF-8（BOM付き）。Excelで開いても文字化けしない
* 参加者は`participantId`（例：P001）だけで識別し、氏名などは記録しない。**自由入力の文章はそのまま記録する**ので、実験の説明・同意書でその旨を伝えること
* プレイヤーの位置（移動の軌跡）は記録しない

## 6.2 保存場所

| 実行のしかた | 保存先 |
|---|---|
| ビルドしたアプリ（実験本番） | アプリ（.exe）と同じフォルダの`ExperimentLogs/` |
| Unityエディタ | `Assets/ExperimentLogs/`（`.gitignore`済み。GitHubには上げない） |

* エディタではUnityがCSVをテキストアセットとして取り込み、`.meta`を作る（ログの中身には影響しない）。`.meta`も`.gitignore`の対象

* ファイル名：`{参加者ID}_{条件}_Q{クエスト番号}_{開始日時}.csv`（例：`P001_B_Q2_20261012_143005.csv`）
* `summary.csv`も同じフォルダ
* 保存先のパスはセッション開始時にConsoleへ`[Log] Session log: …`と出る。タイトル画面の開発者用モーダルの下にも「ログ保存先：…」と表示する

## 6.3 記録するイベント

| event_type | いつ | 主な記録内容 |
|---|---|---|
| `session_start` | MainSceneの開始時 | `detail`にアプリのバージョン・Unityバージョン・AIモデル名・プラットフォーム（参加者ID・条件・クエストは全行の列に入る） |
| `dialogue_start` | NPCに話しかけた | NPC ID・開始ノードID・クエストの状態 |
| `npc_line` | NPCのセリフが表示された | NPC ID・ノードID・セリフ |
| `choice_select` | 選択肢を決定した | NPC ID・ノードID・選択肢の文・何番目か（「入力する」も含む） |
| `free_input_submit` | 自由入力を送信した | NPC ID・ノードID・入力した文章 |
| `free_input_cancel` | 自由入力を「やめる」で閉じた（3.7） | NPC ID・ノードID（書きかけの文章は記録しない）。集計（summary.csv）には入れない |
| `ai_response` | AIの返答が表示された | NPC ID・ノードID・返答・応答時間（ミリ秒）・エラーかどうか・プロンプトの識別子 |
| `dialogue_end` | 会話を閉じた | NPC ID・会話時間・この会話での選択回数・自由入力回数 |
| `quest_start` | 依頼を引き受けた | クエスト番号 |
| `clue_get` | 手がかりを得た | 手がかりID・教えてくれたNPC・`detail`にその時点で集めた手がかりの数（`clues_collected`）と、それまでに話しかけたNPCの人数（`npcs_talked`、依頼人も含む） |
| `quest_complete` | 達成した | 受注から達成までの時間 |
| `settings_open`／`settings_close` | 設定パネルの開閉 | 閉じたときの音量・感度。`duration`は開いていた**実時間**（パネル表示中は`play_time`が止まるため）。スライダーの細かい動きは記録しない |
| `respawn` | 「初期位置に戻る」を押した | 押す前の位置（`from_x`／`from_z`） |
| `session_end` | セッションの終わり | 終わり方（`quest_complete`／`back_to_title`／`app_quit`。それ以外でシーンが消えたときは`scene_unloaded`）・総プレイ時間。会話中・設定パネル表示中に終わった場合は、先にその`dialogue_end`／`settings_close`を書く |

* **AIのエラー**：返答が得られなかったら`is_error=1`にし、`detail`に理由（`error=…`）を書く（4.6）。プロンプトが見つからなかったときも`is_error=1`（`detail`は`prompt=none`）
* `npc_line`はノードを表示するたびに書く（AIの返答のあと同じノードに戻ったときも、もう一度書かれる）
* 会話時間（`dialogue_end`の`duration`）・達成までの時間（`quest_complete`の`duration`）・会話ごとの選択回数と自由入力回数は、`ExperimentLogger`が自分で計算して書く
* **プロンプトの識別子**：使った`PromptData`の場所（例：`Q1/NPC005`）と、本文のハッシュ値（先頭8文字）。実験期間中にプロンプトが変わっていないかを後から確認できる（1.5）

## 6.4 時間

* `timestamp`：PCの時計の日時（例：`2026-10-12T14:30:05.123`）
* `play_time`：MainSceneを開始してからの秒数（小数3桁）。**設定パネルで時間を止めている間は進まない**（`Time.timeSinceLevelLoad`）

会話時間・達成時間などは`play_time`の差で計算する。

## 6.5 実装の構成

`ExperimentLogger`（MainSceneの`GameManager`に付けてある）がファイルの作成・書き込み・集計を担当し、他のスクリプトからは`ExperimentLogger.Log(...)`の1行で呼ぶ。既存クラスの役割は変えず、該当箇所に呼び出しを足しただけ。AIのモデル名は`ChatGPTClient.ModelName`から読む。

| クラス | 場所 | イベント |
|---|---|---|
| `DialogueManager` | `StartNode`／`ShowNode`／選択肢の決定／`SubmitTypedText`／`OnClickCancelInput`／`ShowAIResponse`／`CloseDialogue`／`OpenSettings`／`CloseSettings`／`RespawnPlayer` | dialogue_start／npc_line／choice_select／free_input_submit／free_input_cancel／ai_response／dialogue_end／settings_open／settings_close／respawn |
| `QuestManager` | `StartQuest`／`AddClue`／`Complete` | quest_start／clue_get／quest_complete |
| `SettingsPanelUI` | 「タイトルへ戻る」 | session_end（back_to_title） |
| `DialogueManager` | `EndGame`（終了画面） | session_end（quest_complete） |
| `ExperimentLogger` | 開始時／アプリ終了時（エディタのPlay停止も含む） | session_start／session_end（app_quit） |

## 6.6 イベントログの形式

```csv
session_id,participant_id,condition,quest,timestamp,play_time,event_type,npc_id,node_id,text,player_input,choice_index,clue_id,duration,is_error,detail
```

| 列 | 内容 |
|---|---|
| `session_id` | セッションのID（開始日時＋参加者ID） |
| `participant_id`／`condition`／`quest` | 全行に入れる（複数ファイルを結合して分析しやすいように） |
| `timestamp`／`play_time` | 6.4 |
| `event_type` | 6.3 |
| `npc_id`／`node_id` | 対象のNPCとノード |
| `text` | NPCのセリフ・選んだ選択肢の文・AIの返答 |
| `player_input` | 自由入力の文章 |
| `choice_index` | 選んだ選択肢の順番（0始まり） |
| `clue_id` | 手がかりID |
| `duration` | 会話時間・設定パネルを開いていた時間など（秒） |
| `is_error` | AIのエラーなら1 |
| `detail` | その他（`key=value`を`;`区切り。例：`prompt=Q1/NPC005;hash=3fa2c91b;latency_ms=1840`） |

使わない列は空欄。文章にカンマ・改行・`"`が含まれても崩れないよう、`"`で囲む。

## 6.7 集計ファイル（summary.csv）

1セッション1行。

```csv
session_id,participant_id,condition,quest,start_time,end_reason,total_play_time,quest_start_time,quest_complete_time,quest_duration,dialogue_count,choice_count,free_input_count,ai_error_count,settings_open_count,respawn_count,clue_place_time,clue_time_time,clue_person_time,clue_feature_time,talk_NPC001,talk_NPC002,talk_NPC003,talk_NPC004,talk_NPC005,talk_NPC006
```

* `*_time`：そのイベントが起きた`play_time`（起きなければ空欄）
* `talk_NPC00x`：そのNPCとの会話の回数と合計時間（例：`3/42.5`＝3回・42.5秒）
* イベントログから計算し直せる内容だが、条件A・Bの比較をすぐできるように用意する

## 7.3 プレイヤーとカメラ

* 見た目は購入アセットの`Axe_Warrior`を`PlayerArmature`の子として使う。モデルの横位置は回転の中心に合わせてある（`localPosition.x = 0`。ずれていると片足を軸に回っているように見える）
* カメラは`PlayerFollowCamera`（`Cinemachine3rdPersonFollow`）。`CameraSide = 0.5`でキャラクターを画面の中央に映す（0.5〜1にすると右肩越しの視点になる）
* `ThirdPersonController.cs`（購入アセット）は、このプロジェクト用に手を入れてある（足音まわり・`StopMotion()`）。7.7を参照

## 7.4 音

AudioMixerは使わず、音量を1か所（`AudioVolumeSettings`）で持ち、各`AudioSource`に付けた`VolumeChannel`（BGM／SE）が「元の音量×設定音量」を反映する。

| 種類 | 音源 | 備考 |
|---|---|---|
| BGM | シーンのルートの`BGM`（`Assets/Audio/BGM.wav`、約82秒） | ループ再生・起動時に自動再生・2D。読み込みはStreaming・Vorbis品質70% |
| SE | `Player/PlayerArmature/Audio/`の`Footstep_Concrete`・`Footstep_Land` | 足音・着地音 |

* 初期値はBGM・SEとも80%。保存しない（1.4）
* 新しい音を足すときは、その`AudioSource`に`VolumeChannel`を付ける

## 7.5 空とライティング

* 空はAsset Storeの無料素材「Simple Sky - Cartoon assets」。シーンのルートの`Sky`の中に、空のドーム（`SkyDome`、村の中心(11, 0, 128)・スケール1.3・半径約430m）とローポリの雲12個（`Clouds`）を置いている。どれも影を落とさない
* ドームと雲には、素材のマテリアルをコピーした`Assets/Material/SimpleSky_Day.mat`（UVオフセット**−0.05**＝明るい昼の青空）を使う。オフセットで時間帯が変わる（0.1付近で夕方寄り、0.2で夕方、0.3以降で夜）。ドームの月（`Moon`）と星（`Stars`）は非表示
* ドームはカメラの描画距離（500m）の内側に収めてある。ドームを大きくしたりカメラのFar Clipを小さくしたりすると空が消える
* スカイボックスは使わない。環境光は3色指定（空 RGB(140,184,242)・地平線 RGB(199,209,219)・地面 RGB(107,115,92)）。太陽（`Directional Light`）は色温度6500K（昼の白い光）
* 焼き込みライティングは使わない（`Assets/Settings/MainSceneLighting.lighting`：Baked GI・Realtime GIともオフ）。環境光のデータは`Assets/MainSceneLight/LightingData.asset`

## 7.6 水に入れないようにする壁

* 水面（`Background/Landscape/Water`、y=−0.9）まで岸の地面がなだらかに続いていて、そのままでは浅瀬に入れてしまう。そこでシーンのルートの`WaterBlockers`に、岸に沿って見えない当たり判定の箱（`Blocker`、697個・高さ6m）を並べている
* 0.5m四方ごとに「水面以外の当たり判定の一番高い所が水面より低いか」を調べ、陸と接している水のマスにだけ置いた。桟橋・岩・ボートは陸として扱うので、桟橋の上は先端まで歩ける
* 箱は`Water`レイヤー。カメラの衝突判定（`Default`のみ）に含まれないので、カメラが押し戻されることはない
* 岸の地形・桟橋・水面の高さを変えたら、Unityのメニュー **Tools → 研究用 → 水の壁を作り直す** で作り直す（`Assets/Editor/SceneBuildTools.cs`）

## 7.7 GitHubに含まれないもの・別のPCで開くとき

| もの | 理由 | 別のPCで開くとき |

# 9. 開発の進め方

Claude Codeが本仕様書を参照し、Unity MCP経由で開発する。

## 9.1 設計から実装まで

1. 新しい機能・変更は、まずREADMEに設計を書き、見出しに「**案・レビュー待ち**」と付ける
2. ユーザーが確認・承認する
3. 承認後に実装する（1ファイルずつ）。終わったら見出しを「**承認・実装済み**」にし、READMEの内容を実装に合わせる

## 9.2 基本ルール

* 既存の実装を確認してから変更する。推測だけでUnityの状態を判断せず、Unity MCPで確認する
* 不要な既存機能を削除しない。既存のクラスの役割を尊重する
* 1回の変更で大量のファイルを変更しない
* 変更したらUnityでコンパイルし、Consoleのエラーを確認する。エラーがあれば直してから次へ進む
* 研究仕様（1.6）は勝手に変えない
